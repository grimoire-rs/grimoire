# Grimoire CLI Commands — Quick Reference

Concise index of `grim` CLI commands. Implementation lives under
`src/command/` — read the source for return types, call sites, and report
column formats.

Index of shipped `grim` subcommands — keep in sync with `src/command/`
(one file per subcommand) and `docs/src/commands.md`.

## Command Surface

| Command | Purpose |
|---------|---------|
| `grim init` | Write a fresh `grimoire.toml` in the current directory; `--registry <ref>` seeds the default `[[registries]]` entry |
| `grim add [--kind …] [--name …] [--no-install] [--force] <ref>` | Declare a skill/rule/agent/mcp/bundle in `grimoire.toml`, pin it in the lock immediately, and (by default) materialize just that entry into the detected clients; `--no-install` stops at declare + lock; `--force` overwrites a locally modified artifact / untracked destination with `grim install --force` semantics (inert with `--no-install`) |
| `grim lock` | Resolve floating tags in `grimoire.toml` to digests and write `grimoire.lock` (after hand-edits; `add` locks what it declares) |
| `grim config get\|set [--dry-run]\|unset\|list <key>` | Read and write `grimoire.toml` settings (`[options]`, `[options.tui]`, `[options.vendors.<name>]`) and registry fields via dotted keys; `list` dumps explicitly-set values for the active scope (never merged across scopes); `list [--all]` lists every supported key incl. unset, with JSON items carrying type/title/description/default metadata. `set --dry-run` validates and reports (report gains always-present `dry_run`) without acquiring the write lock or touching the file — same 64/65/79 error envelopes as a real `set`; no `unset --dry-run`. Exit codes: unset `get` → 1, unknown key → 64, bad value → 65. |
| `grim config registry add\|set\|rm\|use\|show\|list\|fields` | Registry lifecycle for `[[registries]]` entries: `add <alias> --oci\|--index <url> [--include <glob>]… [--exclude <glob>]… [--default] [--insecure]`, `set <alias>` (edit in place — same flags as `add` plus `--clear-include`/`--clear-exclude`/`--no-insecure`; applies only the flags given, keeps the entry's position, `--oci`/`--index` swaps the kind clearing the other side, `--default` cannot unset, `--insecure`/`--no-insecure` can; naming no field → 64), `rm <alias>`, `use <alias>` (at-most-one-default, clears prior), `show <alias>`, `list`. Alias not found (`set`/`rm`/`use`/`show`) or dup on `add` → 64. `--include`/`--exclude` are repeatable and **never comma-split** (a comma is glob alternation) — `add`/`set` are the only CLI paths writing a multi-pattern browse filter; `config set registry.<alias>.include` stores exactly one pattern, and `get` comma-joins for display and is not round-trippable. Clearing a list has two supported routes, both silent at any list length and both writing the emptied list as an absent key: `registry set --clear-include`/`--clear-exclude` (conflicts with its own list flag → 64) and `config unset registry.<alias>.include`. `registry set`'s write report carries the always-present `fields` array — one element per field written, in `RegistryField::ALL` order, `{field, action: set, value}` or `{field, action: cleared}` (no `value` key); `[]` on every other write verb. `show`/`list` carry always-present `include`/`exclude` arrays (`[]` unfiltered; plain cell is counts, `—` unfiltered). `fields` lists the 6 addressable per-registry field names (`oci`, `index`, `default`, `include`, `exclude`, `insecure` — **append-only**, positions frozen) and their static type/title/description metadata — no `Context`, no scope resolve, no lock, works with no `grimoire.toml` present (unlike every other `registry` verb) |
| `grim install` | Materialize every locked artifact into the configured AI client(s); no positional — declare via `add`, scope clients via `--client`. Refuses to overwrite an untracked pre-existing destination (65) unless `--force`; adopts identical content into the record |
| `grim status` | Report each declared artifact's state (installed, outdated, modified, …) with bundle provenance; JSON items carry always-present `clients_missing`/`clients_extra` (configured-vs-recorded client drift, local only) and always-present `outputs_pending` (`[{client, path}]`, sorted by client; materialization drift: what `grim install` would write now that the record does not cover — two causes, a new client or a layout move; a deleted file is **not** one of them, it reads `state: missing`; reported under autodetect too, since it asks what install would do rather than what was configured; never moves `state`, never affects the exit code; derived from `install::expected_outputs`, the same seam the installer's no-op check uses). `--check` (network, opt-in) adds a live catalog load populating `deprecated`/`replaced_by`, plus a fresh per-artifact re-resolution populating `update_available`; top-level `checked` gates all three — `false` forces them `null` on every item |
| `grim context` | Read-only introspection of the resolved invocation context: scope, config/lock/state paths (+ existence), effective client set (names only), registry browse set, default registry, offline (+ source). `registries[]` carries always-present `include`/`exclude` browse-filter patterns (`[]` unfiltered, and `[]` for every entry under `--registry`) plus an always-present `insecure` bool — the **authored** `[[registries]]` field, not the effective transport (a host reached over HTTP via the loopback default or `GRIM_INSECURE_REGISTRIES` still reports `false`), so it and `config get registry.<alias>.insecure` always agree **except under `--registry`**, whose synthesized entries carry no authored fields and report `false` for every row — a statement about the browse set only, since `--registry` never narrows the plain-HTTP transport set; plain row appends `, insecure` only when set, then `, N include, M exclude` counts, both omitted entirely when unset/unfiltered. Exits 79 outside a project without `--global` |
| `grim search [query]` | Substring search over the registry catalog (repo, summary, description, keywords); empty query lists all. `--sort <name\|updated\|rating>` (also on `grim tui`) applies the shared `catalog::browse_sort` comparator: `name` ascending case-insensitive · `updated` date descending, undated last · `rating` upvotes descending then date descending, **unrated last, never as 0**. Every mode is total — the final tiebreak is the fully-qualified ref. Given with a query it **replaces** relevance ranking; omitted, ordering is unchanged (relevance when queried, registry order otherwise), so the flag is additive. JSON items carry `rating` as always-present `{up, url}`-or-null (`target` deliberately **not** emitted — opaque forge node id, and no consumer can act on it). Each source's `include`/`exclude` browse filter narrows the rendered rows at read time (`CatalogScope::Browse`) — the shared catalog cache is never narrowed, `--registry` browses unfiltered, and `grim status --check` uses `Complete` and is never filtered. A mis-aimed-pattern warning logs `registry '<name>': filter admitted <M> of <N> repositories; patterns match either the repository path or the fully-qualified reference, and anchor at the candidate's first segment — see https://grimoire.rs/configuration.html#browse-filters` (warn only, exit stays 0) when a non-empty `include` admits nothing from a group that had rows — **only on the unqueried browse**: `<N>` is post-query rows, so under `grim search <query>` the warning is silent (indistinguishable from a deliberate search for a hidden term). A non-empty `exclude` that removes nothing, and an exclude-only filter that empties a source, both stay silent. The 500-repo `MAX_CATALOG_REPOS` cap is applied at build time, **before** the filter — a narrow filter can never widen the window, and `truncated` keeps reporting build-time truncation verbatim |
| `grim rate <ref> [--up\|--remove] [--yes] [--dry-run] [--token-stdin] [--token-host <host>]` | Vote on an artifact through the rating forge the index's `stats.json` sidecar declares (`providers.rating`) — GitHub Discussions `addUpvote`/`removeUpvote`, GitLab work-item `awardEmojiToggle`. No `--registry` field of its own: the global flag already applies (declaring one would collide on the clap arg id, same as `LoginArgs::host`). **Confirms by default** — an interactive run prompts on stderr naming provider + login; a decline exits `0` with no mutation and no `votes.json` write. Non-interactive without `--yes` → 64 (never a hang); `--token-stdin` implies non-interactive so it also requires `--yes`, and the prompt is never rerouted to `/dev/tty`. Credential ladder is grim's **own, narrower** one, not the announce token: `--token-stdin` (else) `GRIM_RATE_TOKEN` → host-matched CI token → `gh`/`glab auth token --hostname` → refuse 80 naming the ladder. **No `--token VALUE`** (CWE-214). Host: `github` ⇒ `api.github.com`, `gitlab` ⇒ `gitlab.com`, overridden by the sidecar's `providers.rating_host` when it declares one — a deliberate reversal of C-007's "never from index-fetched content" (`adr_index_declared_rating_host.md`; `GRIM_RATING_HOST` is **removed**). A declaration is accepted only if it normalises as a bare `host[:port]`, and a **remote** index may not name the loopback set (a local one may — that is the acceptance suite's shape); a rejected one degrades to the default at `debug`. Comparison stays exact (IDNA + ASCII-lowercase via `Url` parse, port included, trailing root dot stripped, **no suffix matching**), redirects `Policy::none()`. **Credential-class gate**: against an index-declared host the two *injected* credentials — `--token-stdin` and `GRIM_RATE_TOKEN` — must be paired with `--token-host <host>` or the run exits 80 **before the credential is read** and never falls through to the host-matched rungs; those rungs (CI token, `gh`/`glab`) need no gate because they only resolve a credential for the host being contacted. A **bare** `--dry-run` is never gated (it reads nothing and is how a client learns the host); `--dry-run --token-stdin` is. **`--dry-run` has two modes (C-023).** Bare: resolves row/provider/host and reports with no credential, forge request or mutation — works offline. With `--token-stdin`: also consumes the credential for **exactly one read-only query** and reports the tri-state `viewer_up` (`true`/`false`/`null` = *not asked or not knowable*) — null on every other path, a completed vote included — so it needs the network and takes 81 under `--offline`. **`--token-stdin` requires `--yes` only on the voting path**, narrowed by `--dry-run` alone (`usage_gate`: `token_stdin && !yes && !dry_run`) — a dry run posts nothing, so there is nothing to confirm; inverting that branch votes unconfirmed. A failed/unauthorised viewer query yields `viewer_up: null` and exit **0**, never `false` (R-3) — but credential *input* errors are unchanged (TTY/multi-line 64, empty 80). `--token-host` declares the injected credential's host and mismatches exit 80 **before the token reaches a header**, on both paths — though on the dry-run path it is only checked when a host resolved (no host ⇒ no request ⇒ nothing to protect). It **stands on its own** — the old "without `--token-stdin` → 64" rule is gone, because `GRIM_RATE_TOKEN` needs the same declaration. Row resolution uses `CatalogScope::Complete`, so a browse filter never makes an artifact unvotable. Report: single object, always-present-null `{ref, action, up, url, provider, host, host_source, viewer_up}` — `host_source` is `default`/`index`/null (null exactly when `host` is), and `index` is precisely when a client must pass `--token-host`; plain stays a 7-column row whose `Voted` cell renders `yes`/`no`/`-` as three distinct cells (unknown must not read as "no") and whose `Host` cell reads `<host> (index)` when declared. Exit codes: `0` voted/retracted/declined/dry-run · `64` usage · `65` no rating on the row, no provider declared, unsupported provider, GraphQL `errors` · `69` unreachable/5xx/secondary limit · `79` no such row or target gone · `80` no credential, 401/403, empty `--token-stdin`, `--token-host` mismatch, an injected credential undeclared against an index-declared host · `81` offline (`--dry-run` exempt) |
| `grim fetch <ref> [--vendor …] [--path …] [--description] [--digest-only] [--out <dir>]` | Print an artifact's content without installing (CLI port of the MCP `grim_fetch` tool). `--description` fetches the repository companion (README, logo, CHANGELOG) instead of the artifact; `--out <dir>` unpacks that companion tree (only valid with `--description`). `--digest-only` resolves the reference to a digest and reports `{ref, digest}` **without downloading the manifest or any blob** — the cheap cache-freshness probe `grimoire-vscode` builds on; it composes with `--description` to probe the companion tag, and rejects `--vendor`/`--path`/`--out` (64). Plain = raw payload (pipe-able, no trailing newline; warnings on stderr); JSON = full fetch report. Never truncates a printed payload (MCP keeps its 256 KiB doc cap). Two download ceilings instead: the declared layer size is checked against the 8 MiB limit before download, and that same declared size then bounds the actual streamed bytes — a registry serving more than it declared aborts mid-transfer into a data error (65) rather than a silent truncation |
| `grim tui` | Interactive catalog browser with live install state (flat list / tree toggle); `--sort <name\|updated\|rating>` is a launch flag (not a keybinding) applying the same `browse_sort` order as `grim search --sort`, and the detail pane gains a `Rating:` row when the browse source published one (absent rating renders no row, never `0`) |
| `grim update [names…]` | Re-resolve floating tags, roll the lock forward, re-materialize what changed **through the same integrity gate as `install`** — a new pin overwrites freely, but a locally-modified artifact is refused (65) until `--force` (changed in 0.13.0; it used to force unconditionally); prunes clean orphans that dropped out of the lock, and reaps a dropped client's outputs when `[options].clients` narrows (`reaped_clients`/`kept_modified_clients` on the JSON row; `--force` reaps a locally-modified one too). No names = everything; names are config binding names, not refs |
| `grim remove <kind> <name>` | Undeclare an artifact (config + lock only; files left on disk) |
| `grim uninstall [--force] <kind> <name>` | Full inverse of install: delete files, drop the install record, undeclare (config + lock). Shared seam reused by the TUI delete action. **Exception:** an artifact a declared bundle still provides keeps its files (a directly-declared one degrades to `remove`; a bundle-only member is a no-op — remove the bundle to remove it). A managed MCP config entry that drifted from the recorded value is refused pre-flight (65, `reason: modified`, forceable) so nothing is half-removed; `--force` removes it. File outputs are deleted regardless of the flag |
| `grim build <path>` | Validate and pack a local skill/rule/agent/mcp/bundle without pushing (release dry run) |
| `grim release <path> <ref>` | Push a single artifact to a registry (validate, pack, push with cascade tags); `--push-registry <host[/prefix]>` pushes to a deviating endpoint while every baked/reported name keeps the reference's registry (the pull name; malformed value → 65), report gains always-present `pushed_to` (null when inactive) |
| `grim publish` | Batch-release all packages declared in a `publish.toml` manifest; validates whole manifest before any push; fixed kind order (skills → rules → agents → mcp → bundles), skip-existing by default. Optional manifest `push_registry` / `--push-registry` flag (flag wins) splits the push endpoint from the pull-named manifest `registry` (references, source fallback, pinned member ids, announce pointers, report `ref` all stay pull-named; per-entry `pushed_to` reports the push side) |
| `grim login [<registry>]` | Authenticate to a registry; store the credential via the docker-compatible credential store (helper or, with `--allow-insecure-store`, plaintext). Verifies the credential against the registry **before** storing by default (`/v2/` ping + challenge answer, scope-less): rejected → 80 nothing stored, unreachable/5xx/429 → 69 nothing stored, anonymous registry → 0 stored (`verification: no-auth-required`). `--no-verify` skips (store-only, `verification: skipped`); offline skips silently with a warning unless `--verify` is explicit → 81 |
| `grim logout [<registry>]` | Remove a stored registry credential (idempotent — exits 0 when nothing is stored) |
| `grim schema --kind <config\|publish\|lock\|mcp>` | Print the JSON Schema for `grimoire.toml`, `publish.toml`, `grimoire.lock`, or the MCP descriptor (`mcp/<name>.toml`) to stdout (generated from the real parse structs); emits a document, not a `Printable` report |
| `grim completions <shell>` | Print a `clap_complete`-generated completion script (`bash`, `elvish`, `fish`, `powershell`, `zsh`) to stdout; no eval hook, no shell auto-detect. Missing/unrecognized `<shell>` → 64. Document emitter, not a `Printable` report |
| `grim mcp [--allow-writes]` | Run a local STDIO Model Context Protocol server (rmcp SDK). Long-running, `Printable`-exempt (returns `ExitCode` directly, like `tui`/`schema`); stdout is the JSON-RPC channel. Read tools (`grim_search`, `grim_status`, `grim_fetch`) always on; the write tool `grim_render` gated behind `--allow-writes` (rmcp `disable_route`: hidden + rejected). Scope per tool call (`global`/`config`/`workspace` args; precedence in that order, default cwd walk-up) — launch scope flags removed, `--global`/`--config` exit 64 |
| `grim --version` | Print the compiled version (clap built-in; no subcommand) |

Global flags (`src/cli/options.rs` `GlobalOptions`): `--format`,
`--color <auto|always|never>` (default `auto`; styles clap help/errors and
`--format json`; `auto` is TTY-gated and honors `NO_COLOR`/`CLICOLOR`/
`CLICOLOR_FORCE`/`TERM=dumb`, `always` overrides `NO_COLOR`),
`--progress <auto|json|none>` (experimental; NDJSON events on stderr),
`--offline`, `--log-level`, `--config <path>`, `--global`,
`--registry <ref>` (repeatable / comma-separated).

`login`/`logout` resolve the registry from the positional argument when
given: an argument matching a `[[registries]]` alias substitutes that
entry's locator, anything else is taken as a literal hostname. With no
argument, the resolved scope's registry set supplies the primary —
`--registry` flag > `[[registries]]` default > `GRIM_DEFAULT_REGISTRY` >
project then global `[options].default_registry` — the same
`resolve_registries` chain `add`/`search` use, with `--config`/`--global`
selecting the scope as they do for every other command. Config **is**
consulted on this path; `Context::default_registry()` is a superseded
accessor with no production caller, so do not cite it as evidence
otherwise. The built-in `ghcr.io/grimoire-rs` fallback is deliberately not
substituted here — storing or erasing a credential for a registry the user
never named is a silent surprise — so an otherwise-unresolved set exits 78.
A global config that fails to load is fatal for `login` (78) and degrades
for `logout`, which still recovers the alias map when the file parsed and
only validation failed.
They read and write the docker config at `$DOCKER_CONFIG/config.json`
(default `~/.docker/config.json`) — the same file the credential read path
consults — so credentials round-trip with `docker login`.

## Conventions (apply as commands land)

- **One file per subcommand** under `src/command/`.
- **Typed identifiers**: parse user-supplied references into domain types
  early; the rest of the command works on typed values, not raw strings.
- **Report actual results**: a command reports what happened, not an echo
  of its input. Operations return enough data to build accurate output.
- **Exit codes**: follow `quality-rust-exit_codes.md` — usage errors,
  data errors, and I/O errors map to distinct, documented codes.
- **Output**: structured data goes through the shared output trait so
  `--format json` and the plain table render from one source.
