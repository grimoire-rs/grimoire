# Grimoire CLI Commands — Quick Reference

Concise index of `grim` CLI commands. Implementation lives under
`src/command/` — read the source for return types, call sites, and report
column formats.

Index of shipped `grim` subcommands — keep in sync with `src/command/`
(one file per subcommand) and `docs/src/content/docs/commands.md`.

## Command Surface

| Command | Purpose |
|---------|---------|
| `grim init` | Write a fresh `grimoire.toml` in the current directory; `--registry <ref>` seeds the default `[[registries]]` entry |
| `grim add [--kind …] [--name …] [--no-install] [--force] [--[no-]trust-hooks] <ref>` | Declare a skill/rule/agent/mcp/hook/bundle in `grimoire.toml`, pin it in the lock immediately, and (by default) materialize just that entry into the detected clients; `--no-install` stops at declare + lock; `--force` overwrites a locally modified artifact / untracked destination with `grim install --force` semantics (inert with `--no-install`). A hook declares and locks normally even with the feature flag off — the install half skips with a warning and `status` reads `gated`; the kind-inference path deliberately carries **no** flag check, so flipping the flag never requires re-running `add`. **`add` is one of exactly three write seams for the workspace consent record** (with `grim hook allow` and an accepted prompt): typing a ref *is* the declaration gesture (`adr_artifact_trust_model.md` decision 1), and a bundle records the **resolved** hook member set so a later-added member drifts rather than arming silently |
| `grim lock` | Resolve floating tags in `grimoire.toml` to digests and write `grimoire.lock` (after hand-edits; `add` locks what it declares) |
| `grim config get\|set [--dry-run]\|unset\|list <key>` | Read and write `grimoire.toml` settings (`[options]`, `[options.tui]`, `[options.vendors.<name>]`) and registry fields via dotted keys; `list` dumps explicitly-set values for the active scope (never merged across scopes); `list [--all]` lists every supported key incl. unset, with JSON items carrying type/title/description/default metadata. `set --dry-run` validates and reports (report gains always-present `dry_run`) without acquiring the write lock or touching the file — same 64/65/79 error envelopes as a real `set`; no `unset --dry-run`. Exit codes: unset `get` → 1, unknown key → 64, bad value → 65. |
| `grim config registry add\|set\|rm\|use\|show\|list\|fields` | Registry lifecycle for `[[registries]]` entries: `add <alias> --oci\|--index <url> [--include <glob>]… [--exclude <glob>]… [--default] [--insecure]`, `set <alias>` (edit in place — same flags as `add` plus `--clear-include`/`--clear-exclude`/`--no-insecure`; applies only the flags given, keeps the entry's position, `--oci`/`--index` swaps the kind clearing the other side, `--default` cannot unset, `--insecure`/`--no-insecure` can; naming no field → 64), `rm <alias>`, `use <alias>` (at-most-one-default, clears prior), `show <alias>`, `list`. Alias not found (`set`/`rm`/`use`/`show`) or dup on `add` → 64. `--include`/`--exclude` are repeatable and **never comma-split** (a comma is glob alternation) — `add`/`set` are the only CLI paths writing a multi-pattern browse filter; `config set registry.<alias>.include` stores exactly one pattern, and `get` comma-joins for display and is not round-trippable. Clearing a list has two supported routes, both silent at any list length and both writing the emptied list as an absent key: `registry set --clear-include`/`--clear-exclude` (conflicts with its own list flag → 64) and `config unset registry.<alias>.include`. `registry set`'s write report carries the always-present `fields` array — one element per field written, in `RegistryField::ALL` order, `{field, action: set, value}` or `{field, action: cleared}` (no `value` key); `[]` on every other write verb. `show`/`list` carry always-present `include`/`exclude` arrays (`[]` unfiltered; plain cell is counts, `—` unfiltered). **No per-registry field answers hook arming** — that question is workspace-scoped (`grim hook allow`, a record under `$GRIM_HOME/hooks/consent/`), never a registry field: the branch's `trust_hooks` tri-state and its emit-only-when-true serializer hazard are **gone**, along with the scope-precedence table and the bare-host/`insecure`/`index` matching rules that keyed a *name* on the publisher side. `fields` lists the 6 addressable per-registry field names (`oci`, `index`, `default`, `include`, `exclude`, `insecure` — **append-only**, positions frozen; `RegistryField::ALL` is back to the six shipped names in their shipped order) and their static type/title/description metadata — no `Context`, no scope resolve, no lock, works with no `grimoire.toml` present (unlike every other `registry` verb) |
| `grim install [--[no-]trust-hooks]` | Materialize every locked artifact into the configured AI client(s); no positional — declare via `add`, scope clients via `--client`. Refuses to overwrite an untracked pre-existing destination (65) unless `--force`; adopts identical content into the record. **Hooks are the one kind declined on policy rather than capability**: a locked hook arms only past the `[options.experimental] hooks` flag *and* the resolved workspace's consent record, otherwise `InstallOutcome::Skipped` + one warning naming the single cause, exit stays 0. **`install` never writes a consent record** — it converges what is already declared, and a cloned repo's `grimoire.toml` is not the user's gesture; that negative is the T3 control and is asserted by an acceptance test, not by visibility. Global scope is always consented and carries no record. A hook whose pinned registry host is non-loopback and reached over plain HTTP does not arm at all (`insecure-transport`), independent of consent and unescapable from any file. `--trust-hooks` / `--no-trust-hooks` (also on `update`/`add`) is a clap `overrides_with` pair resolving to one tri-state; it arms or refuses **per invocation**, writes no record, and does **not** enable the feature flag. **The pair beats the consent record in both directions** — owner decision 2026-08-28, N4: a flag typed on this run is the most explicit answer there is, and no file can type one. Convergence derives its own client set from the hook-capable roster and ignores the caller's, so every command is idempotent and self-healing regardless of what it was asked to do — do **not** narrow it to the clients a command happened to touch |
| `grim status` | Report each declared artifact's state (installed, outdated, modified, plus the hook-only `gated`/`not-armed`/`untrusted`) with bundle provenance; a hook row carries the always-present `arming` array (`{client, cause, message, transient}`, sorted by client, `[]` = armed everywhere) whose `cause` is the closed kebab-case `HookArmingCause` set and is the field consumers branch on — never `message`. A hook armed via `--trust-hooks` reports `installed`, not `not-armed`: `hook_arming` consults the **dispatch table first** (`armed_pairs`, via `existing_root_token` so no key material is ever minted on a read path), because the table is the machine-local arming authority and is derived rather than recorded. The consent record alone would under-claim for every `--trust-hooks` run, which is the state every CI run is in. Consent contributes two `gated` causes — `workspace-not-consented` (no record) and `consent-drifted` (a record that no longer covers what the scope declares — a new binding or a new repository; a *version bump* is deliberately not drift) — keeping the state token the registry-scoped cause they replace already shipped with, because both are deliberate policy answers rather than something grim failed at. The relocated plain-HTTP gate is `insecure-transport`, orthogonal to consent and `not-armed`: grim will not work around it, so it groups with `grim-home-relative` rather than with the two consent causes. The split closes issue #92 on the axis that turned out to matter — never-consented vs consented-then-drifted, rather than never-granted vs explicitly-opted-out; JSON items carry always-present `clients_missing`/`clients_extra` (configured-vs-recorded client drift, local only) and always-present `outputs_pending` (`[{client, path}]`, sorted by client; materialization drift: what `grim install` would write now that the record does not cover — two causes, a new client or a layout move; a deleted file is **not** one of them, it reads `state: missing`; reported under autodetect too, since it asks what install would do rather than what was configured; never moves `state`, never affects the exit code; derived from `install::expected_outputs`, the same seam the installer's no-op check uses). `--check` (network, opt-in) adds a live catalog load populating `deprecated`/`replaced_by`, plus a fresh per-artifact re-resolution populating `update_available`; top-level `checked` gates all three — `false` forces them `null` on every item |
| `grim context` | Read-only introspection of the resolved invocation context: scope, config/lock/state paths (+ existence), effective client set (names only), registry browse set, default registry, offline (+ source). `registries[]` carries always-present `include`/`exclude` browse-filter patterns (`[]` unfiltered, and `[]` for every entry under `--registry`) plus an always-present `insecure` bool — the **authored** `[[registries]]` field, not the effective transport (a host reached over HTTP via the loopback default or `GRIM_INSECURE_REGISTRIES` still reports `false`), so it and `config get registry.<alias>.insecure` always agree **except under `--registry`**, whose synthesized entries carry no authored fields and report `false` for every row — a statement about the browse set only, since `--registry` never narrows the plain-HTTP transport set; plain row appends `, insecure` only when set, then `, N include, M exclude` counts, both omitted entirely when unset/unfiltered. Exits 79 outside a project without `--global` |
| `grim search [query]` | Searches the registry catalog: the artifact name (repo leaf) and keywords match fuzzy subsequence (skim score ≥ 12/char, with an exact/whole-word name bonus); summary, description, and the namespace path match by word prefix (a term matches the start of a word; a term carrying a separator like `-`/`.`/`/` must appear contiguously); the registry host is not searched by a plain word, but a term containing `/`, `.`, or `:` matches the full reference including host. Shared with the TUI `/` filter and MCP `grim_search`; empty query lists all. Results are ranked by relevance and cut below `options.search_min_relevance` percent of the best (default 50, `0` off, max 100 — measured against the best remaining hit when nothing matches by name); hidden rows are reported on stderr (`N weaker matches hidden; set options.search_min_relevance to 0 to list all`). `--sort <name\|updated\|rating\|downloads>` (also on `grim tui`) reorders only the kept set — never widening what the cutoff dropped — applying the shared `catalog::browse_sort` comparator: `name` ascending case-insensitive · `updated` date descending, undated last · `rating` upvotes descending then date descending, **unrated last, never as 0** · `downloads` total descending then date descending, **uncounted last, never as 0**. Every mode is total — the final tiebreak is the fully-qualified ref. Given with a query it **replaces** relevance ranking; omitted, ordering is unchanged (relevance when queried, registry order otherwise), so the flag is additive. JSON items carry `rating` as always-present `{up, url}`-or-null (`target` deliberately **not** emitted — opaque forge node id, and no consumer can act on it) and `downloads` as always-present `{total, as_of, versions}`-or-null (an object, never a bare number, so `as_of`/`versions` could land at all; `as_of` may itself be null; `versions` is the per-release breakdown as an ORDERED array, highest release first — grim sorts by semver so no consumer compares tags — and `[]` when the producer published none; `total` is never the sum of `versions`, since a channel tag carries traffic naming no release; null means **unknown**, never 0, and is the common case — only an Artifactory-backed index publishes a per-artifact counter at all). The two sidecar signals are independent: rated-and-uncounted and counted-and-unrated are both normal. Each source's `include`/`exclude` browse filter narrows the rendered rows at read time (`CatalogScope::Browse`) — the shared catalog cache is never narrowed, `--registry` browses unfiltered, and `grim status --check` uses `Complete` and is never filtered. A mis-aimed-pattern warning logs `registry '<name>': filter admitted <M> of <N> repositories; patterns match either the repository path or the fully-qualified reference, and anchor at the candidate's first segment — see https://grimoire.rs/configuration.html#browse-filters` (warn only, exit stays 0) when a non-empty `include` admits nothing from a group that had rows — **only on the unqueried browse**: `<N>` is post-query rows, so under `grim search <query>` the warning is silent (indistinguishable from a deliberate search for a hidden term). A non-empty `exclude` that removes nothing, and an exclude-only filter that empties a source, both stay silent. The 500-repo `MAX_CATALOG_REPOS` cap is applied at build time, **before** the filter — a narrow filter can never widen the window, and `truncated` keeps reporting build-time truncation verbatim |
| `grim rate <ref> [--up\|--remove] [--yes] [--dry-run] [--token-stdin] [--token-host <host>]` | Vote on an artifact through the rating forge the index's `stats.json` sidecar declares (`providers.rating`) — GitHub Discussions `addUpvote`/`removeUpvote`, GitLab work-item `awardEmojiToggle`. No `--registry` field of its own: the global flag already applies (declaring one would collide on the clap arg id, same as `LoginArgs::host`). **Confirms by default** — an interactive run prompts on stderr naming provider + login; a decline exits `0` with no mutation and no `votes.json` write. Non-interactive without `--yes` → 64 (never a hang); `--token-stdin` implies non-interactive so it also requires `--yes`, and the prompt is never rerouted to `/dev/tty`. Credential ladder is grim's **own, narrower** one, not the announce token: `--token-stdin` (else) `GRIM_RATE_TOKEN` → host-matched CI token → `gh`/`glab auth token --hostname` → refuse 80 naming the ladder. **No `--token VALUE`** (CWE-214). Host: `github` ⇒ `api.github.com`, `gitlab` ⇒ `gitlab.com`, overridden by the sidecar's `providers.rating_host` when it declares one — a deliberate reversal of C-007's "never from index-fetched content" (`adr_index_declared_rating_host.md`; `GRIM_RATING_HOST` is **removed**). A declaration is accepted only if it normalises as a bare `host[:port]`, and a **remote** index may not name the loopback set (a local one may — that is the acceptance suite's shape); a rejected one degrades to the default at `debug`. Comparison stays exact (IDNA + ASCII-lowercase via `Url` parse, port included, trailing root dot stripped, **no suffix matching**), redirects `Policy::none()`. **Credential-class gate**: against an index-declared host the two *injected* credentials — `--token-stdin` and `GRIM_RATE_TOKEN` — must be paired with `--token-host <host>` or the run exits 80 **before the credential is read** and never falls through to the host-matched rungs; those rungs (CI token, `gh`/`glab`) need no gate because they only resolve a credential for the host being contacted. A **bare** `--dry-run` is never gated (it reads nothing and is how a client learns the host); `--dry-run --token-stdin` is. **`--dry-run` has two modes (C-023).** Bare: resolves row/provider/host and reports with no credential, forge request or mutation — works offline. With `--token-stdin`: also consumes the credential for **exactly one read-only query** and reports the tri-state `viewer_up` (`true`/`false`/`null` = *not asked or not knowable*) — null on every other path, a completed vote included — so it needs the network and takes 81 under `--offline`. **`--token-stdin` requires `--yes` only on the voting path**, narrowed by `--dry-run` alone (`usage_gate`: `token_stdin && !yes && !dry_run`) — a dry run posts nothing, so there is nothing to confirm; inverting that branch votes unconfirmed. A failed/unauthorised viewer query yields `viewer_up: null` and exit **0**, never `false` (R-3) — but credential *input* errors are unchanged (TTY/multi-line 64, empty 80). `--token-host` declares the injected credential's host and mismatches exit 80 **before the token reaches a header**, on both paths — though on the dry-run path it is only checked when a host resolved (no host ⇒ no request ⇒ nothing to protect). It **stands on its own** — the old "without `--token-stdin` → 64" rule is gone, because `GRIM_RATE_TOKEN` needs the same declaration. Row resolution uses `CatalogScope::Complete`, so a browse filter never makes an artifact unvotable. Report: single object, always-present-null `{ref, action, up, url, provider, host, host_source, viewer_up}` — `host_source` is `default`/`index`/null (null exactly when `host` is), and `index` is precisely when a client must pass `--token-host`; plain stays a 7-column row whose `Voted` cell renders `yes`/`no`/`-` as three distinct cells (unknown must not read as "no") and whose `Host` cell reads `<host> (index)` when declared. Exit codes: `0` voted/retracted/declined/dry-run · `64` usage · `65` no rating on the row, no provider declared, unsupported provider, GraphQL `errors` · `69` unreachable/5xx/secondary limit · `79` no such row or target gone · `80` no credential, 401/403, empty `--token-stdin`, `--token-host` mismatch, an injected credential undeclared against an index-declared host · `81` offline (`--dry-run` exempt) |
| `grim fetch <ref> [--vendor …] [--path …] [--description] [--digest-only] [--out <dir>]` | Print an artifact's content without installing (CLI port of the MCP `grim_fetch` tool). `--description` fetches the repository companion (README, logo, CHANGELOG) instead of the artifact; `--out <dir>` unpacks that companion tree (only valid with `--description`). `--digest-only` resolves the reference to a digest and reports `{ref, digest}` **without downloading the manifest or any blob** — the cheap cache-freshness probe `grimoire-vscode` builds on; it composes with `--description` to probe the companion tag, and rejects `--vendor`/`--path`/`--out` (64). Plain = raw payload (pipe-able, no trailing newline; warnings on stderr); JSON = full fetch report. Never truncates a printed payload (MCP keeps its 256 KiB doc cap). Two download ceilings instead: the declared layer size is checked against the 8 MiB limit before download, and that same declared size then bounds the actual streamed bytes — a registry serving more than it declared aborts mid-transfer into a data error (65) rather than a silent truncation |
| `grim export plugin [REFS…] [--name …] [--plugin …] [--marketplace <path>] [--client …] [--zip] [-o <dir>] [--version …] [--description …] [--logo <path>] [--project] [--force]` | Render locked artifacts as a Claude-family (`.claude-plugin/plugin.json`) or Agent Plugins (`plugin.json` + `mcp.json`) plugin, directory or `--zip`, so a client without grim installs it directly. Ad-hoc (`REFS…`, in-memory manifest, no lock read/written) or declared (`--plugin`/`--marketplace`, re-resolves only stale plugins, writes `marketplace.lock`); mutually exclusive at the clap level. Member admission and MCP-shape projection live in `export::family`; rename in `export::rename` (fails closed: invalid name, kind-collision, or a stale reference the rename left behind all exit 65 before anything is written). `plugin.json` `description` is the base text alone (≤ 500 UTF-16 units: an authored one over it → 65, an annotation is cut); a generated root `README.md` carries the uncut text, the per-client omissions and the on-ramp; a logo (`--logo`/declared `logo`, png/svg ≤ 1 MiB, else 65) ships as `assets/logo.<ext>`, referenced for Agent Plugins under `extensions."com.openai".interface.logo`. Member fetches drive the `--progress` sinks. `--project` renders the project's fresh `grimoire.lock` (via `install::fresh_lock`: missing 79, stale 65) as one plugin, no resolution; name/metadata from flags then `grimoire.toml` `[plugin]` (`config::plugin_meta::PluginMeta`, outside the declaration hash; name missing → 64). A `marketplace.toml` plugin may declare `project = <dir>` instead of `include`: pins from that project's lock, per-field metadata fallback to its `[plugin]`, no `marketplace.lock` part, and `grim update --marketplace` skips it (naming it → 64). Output is refused (65, forceable) over an untracked existing path; reproducible byte-for-byte given the same manifest, lock, and grim build |
| `grim tui` | Interactive catalog browser with live install state (flat list / tree toggle); `--sort <name\|updated\|rating\|downloads>` (else `[options.tui].sort`) seeds the browse order, `[options.tui].sort_order` (`asc`\|`desc`, else the mode's natural direction) its direction; the `s` key cycles the order live (default → name → updated → rating → downloads) and `S` flips the direction — the same `browse_sort` order as `grim search --sort`. In tree view a sorted browse orders leaves within each group by that order instead of by label; the active order is named in the Catalog title (`sort: rating desc`). Both keys are enum rows in `grim config list --all` with `default: null` (unset `sort` is the kind grouping, unset `sort_order` depends on `sort`) — `ValueType::Enum.default` is `Option` for exactly this. The list carries right-aligned `Rating` and `Downloads` columns (`-` when the source published none, never `0`), the flat multi-registry Registry column shows the alias alone (locator when none) and is `fit`-truncated to `W_REGISTRY`, and the detail pane gains `Rating:` / `Downloads:` rows when the browse source published them (absent renders no row, never `0`). A search started with `/` flattens the tree into a ranked list for as long as the query holds a text term (a kind-only query like `skill` keeps the tree); it shares the matcher and the `options.search_min_relevance` cutoff with `grim search`. `i`/`u`/`d` on more than one artifact (a marked set, or a group in tree view) opens a batch confirmation naming the count and source before acting — Cancel preselected, no `y` shortcut, `→`/`←` or `h`/`l` switch buttons, `q` quits |
| `grim update [names…]` | **Never writes a consent record** (write seam is `hook allow` / `add` / an accepted prompt). Re-resolve floating tags, roll the lock forward, re-materialize what changed **through the same integrity gate as `install`** — a new pin overwrites freely, but a locally-modified artifact is refused (65) until `--force` (changed in 0.13.0; it used to force unconditionally); prunes clean orphans that dropped out of the lock, and reaps a dropped client's outputs when `[options].clients` narrows (`reaped_clients`/`kept_modified_clients` on the JSON row; `--force` reaps a locally-modified one too). No names = everything; names are config binding names, not refs. `--marketplace <path>` (conflicts with `--client`/`--force`, needs no project) rolls a declared plugin's `marketplace.lock` forward instead — installs nothing; names become `<plugin>`/`<plugin>:<member>` selectors; JSON rows gain an always-present `plugin` field (`null` outside this mode) |
| `grim remove <kind> <name>` | Undeclare an artifact (config + lock only; files left on disk). `<kind>` accepts `hook` |
| `grim uninstall [--force] <kind> <name>` | Full inverse of install: delete files, drop the install record, undeclare (config + lock). `<kind>` accepts `hook`, whose inverse also reaps the dispatch row **and** the client registration. Shared seam reused by the TUI delete action. **Exception:** an artifact a declared bundle still provides keeps its files (a directly-declared one degrades to `remove`; a bundle-only member is a no-op — remove the bundle to remove it). A managed MCP config entry that drifted from the recorded value is refused pre-flight (65, `reason: modified`, forceable) so nothing is half-removed; `--force` removes it. File outputs are deleted regardless of the flag |
| `grim build <path>` | Validate and pack a local skill/rule/agent/mcp/hook/bundle without pushing (release dry run). `--kind` accepts `hook` — **appended** to a frozen value set, never inserted. Path inference tests `SKILL.md` **before** `hook.toml` (both require `is_dir()`) so a skill shipping a `hook.toml` stays a skill (Principle 9); a hook directory without `SKILL.md` needs no flag. Hook-specific build refusals (exit 65): a `matcher` outside `MATCHER_ALLOWED` / over `MATCHER_MAX_BYTES`; a handler whose `argv[0]` or `command` first token resolves to a payload-relative file (an OCI-fetched payload arrives `0o644`, so the exec bit is never load-bearing); a `policy` or vendor-override value using a TOML datetime / local-date / local-time, which the `serde_json::Value` model cannot re-emit without leaking a private sentinel; and a `ClientTarget::ALL` name used as anything but a vendor override |
| `grim describe <ref>` | Report an artifact's manifest-level metadata — kind, curated + verbatim annotations, tags, `has_description` — **without** downloading its content. Single-object report; every field always present, `kind` null for a foreign manifest. CLI twin of the MCP `grim_describe` tool |
| `grim release <path> <ref>` | Push a single artifact to a registry (validate, pack, push with cascade tags); `--push-registry <host[/prefix]>` pushes to a deviating endpoint while every baked/reported name keeps the reference's registry (the pull name; malformed value → 65), report gains always-present `pushed_to` (null when inactive) |
| `grim publish` | Batch-release all packages declared in a `publish.toml` manifest; validates whole manifest before any push; fixed kind order (skills → rules → agents → mcp → **hooks** → bundles — hooks appended after `mcp`, before `bundles`, so a bundle declaring a hook member finds it pushed; no existing kind's relative position moved), conventional hook source path `hooks/{name}/`, skip-existing by default. Optional manifest `push_registry` / `--push-registry` flag (flag wins) splits the push endpoint from the pull-named manifest `registry` (references, source fallback, pinned member ids, announce pointers, report `ref` all stay pull-named; per-entry `pushed_to` reports the push side) |
| `grim login [<registry>]` | Authenticate to a registry; store the credential via the docker-compatible credential store (helper or, with `--allow-insecure-store`, plaintext). Verifies the credential against the registry **before** storing by default (`/v2/` ping + challenge answer, scope-less): rejected → 80 nothing stored, unreachable/5xx/429 → 69 nothing stored, anonymous registry → 0 stored (`verification: no-auth-required`). `--no-verify` skips (store-only, `verification: skipped`); offline skips silently with a warning unless `--verify` is explicit → 81 |
| `grim logout [<registry>]` | Remove a stored registry credential (idempotent — exits 0 when nothing is stored) |
| `grim schema --kind <config\|publish\|lock\|mcp\|hook>` | Print the JSON Schema for `grimoire.toml`, `publish.toml`, `grimoire.lock`, the MCP descriptor (`mcp/<name>.toml`), or the hook manifest (`hook.toml`) to stdout (generated from the real parse structs); emits a document, not a `Printable` report. The clap `about` string enumerates all five (`grimoire.toml, publish.toml, grimoire.lock, mcp/<name>.toml, or hook.toml`) — a ⚠ note here claiming it omits `mcp` and `hook` was itself stale and is removed |
| `grim completions <shell>` | Print a `clap_complete`-generated completion script (`bash`, `elvish`, `fish`, `powershell`, `zsh`) to stdout; no eval hook, no shell auto-detect. Missing/unrecognized `<shell>` → 64. Document emitter, not a `Printable` report |
| `grim mcp [--allow-writes]` | Run a local STDIO Model Context Protocol server (rmcp SDK). Long-running, `Printable`-exempt (returns `ExitCode` directly, like `tui`/`schema`); stdout is the JSON-RPC channel. Read tools (`grim_search`, `grim_status`, `grim_fetch`) always on; the write tool `grim_render` gated behind `--allow-writes` (rmcp `disable_route`: hidden + rejected). Scope per tool call (`global`/`config`/`workspace` args; precedence in that order, default cwd walk-up) — launch scope flags removed, `--global`/`--config` exit 64 |
| `grim hook allow [path]` | Record the resolved workspace's consent to arming the hooks it currently declares, at `$GRIM_HOME/hooks/consent/<workspace-key>.json` (`workspace-key` = `hook_dispatch::workspace_key`, SHA-256 of the workspace path in hex — reused, never re-spelled, so the record and the payload directory agree by construction). Ordinary scope-resolving `Printable` single-object report (`{workspace, action, hooks}`), wired like `hook list`. `--global` (or a resolved global scope) exits **64**: the global toolchain is always consented and carries no record, so the ask has no meaning — a usage error, not a failed write. Consent is not arming; convergence still has to run. `hooks` stores `<binding>@<registry>/<repository>` — no tag, no digest — so a version bump never re-gates while a new binding or repository does |
| `grim hook revoke [path]` (alias `deny`) | Remove the resolved workspace's consent record. The alias exists because `direnv` — the precedent `adr_hook_workspace_consent.md` cites — calls this operation `deny`, with `revoke` as its own alias for it; the report's `action` stays `revoked`/`not-consented` whichever word is typed, since it names the operation and consumers branch on it. **The alias adds no fourth state**: consent is absent, granted or drifted, and *denied* is deliberately the same state as never-answered — the default is already deny, so a recorded refusal buys silence rather than safety and would leave arming withheld with no cause to report. **Idempotent**: `Removed` / `Absent`, both exit **0** — revoking what was never granted leaves exactly the state asked for, and erroring on the command's most ordinary outcome would be the defect. `--global` needs no refusal, unlike `allow`: global scope never writes a consent record, so there is nothing to remove and the answer is `Absent` (exit 0, `not-consented`) by construction. Like clearing the feature flag it does not disarm by itself: the next `grim install` converges |
| `grim hook list` | List declared hooks with tier, events, and per-client arming state. Ordinary scope-resolving `Printable` report (`{artifact, id, tier, events, state, arming}`, one item per `[[hooks]]` entry, `arming` nested not flattened). Verdicts must come from `status.rs`'s `hook_arming` seam, never a second derivation of the same gates. The `[[hooks]]` entries come from the artifact's **materialized payload**, whose directory is derived from `$GRIM_HOME` and the resolved scope (`hook_dispatch::payload_dir`), never from the install record (SEC-1). A gated hook is skipped before its blob is fetched (S-001), so it has no manifest to enumerate: that artifact contributes no items and one stderr **warning** naming it — degrade, never fail (I3), and never silence |
| `grim hook run --client <c> --event <e> --table <abs> --root <token>` | Dispatch armed hooks for one client event. **Not intended for direct invocation** — its caller is the launcher grim generates, the same "documented but not for you" framing `grim mcp` gets. Reads **only** the `--table` file: no scope resolution, no config, no `Context`, no env data root (source-level import ban, asserted in `src/command/hook/mod.rs`; `hook/list.rs` is the deliberate exemption). **Exits 0 on every path grim controls** — unknown event, unknown root token, relative `--table`, missing table, failed handler — because a client that fails closed on a non-zero hook exit must never be denied a tool call by grim's internals. `--table` must be absolute (a relative one would resolve against the client-spawned CWD, i.e. the workspace, making the table repo-plantable); `--client` and `--root` are lookup keys only, never trust inputs, and `--root` is never compared against the CWD |
| `grim --version` | Print the compiled version (clap built-in; no subcommand) |

Global flags (`src/cli/options.rs` `GlobalOptions`): `--format`,
`--color <auto|always|never>` (default `auto`; styles clap help/errors and
`--format json`; `auto` is TTY-gated and honors `NO_COLOR`/`CLICOLOR`/
`CLICOLOR_FORCE`/`TERM=dumb`, `always` overrides `NO_COLOR`),
`--progress <auto|json|none>` (experimental; NDJSON events on stderr),
`--offline`, `--log-level`, `--config <path>`, `--global`,
`--registry <ref>` (repeatable / comma-separated).

`login`/`logout` resolve the registry from the positional argument when
given: an argument matching a `[[registries]]` alias substitutes that
entry's locator, anything else is taken as a literal hostname. With no
argument, the resolved scope's registry set supplies the primary —
`--registry` flag > `[[registries]]` default > `GRIM_DEFAULT_REGISTRY` >
project then global `[options].default_registry` — the same
`resolve_registries` chain `add`/`search` use, with `--config`/`--global`
selecting the scope as they do for every other command. Config **is**
consulted on this path; `Context::default_registry()` is a superseded
accessor with no production caller, so do not cite it as evidence
otherwise. The built-in `ghcr.io/grimoire-rs` fallback is deliberately not
substituted here — storing or erasing a credential for a registry the user
never named is a silent surprise — so an otherwise-unresolved set exits 78.
A global config that fails to load is fatal for `login` (78) and degrades
for `logout`, which still recovers the alias map when the file parsed and
only validation failed.
They read and write the docker config at `$DOCKER_CONFIG/config.json`
(default `~/.docker/config.json`) — the same file the credential read path
consults — so credentials round-trip with `docker login`.

## Conventions (apply as commands land)

- **One file per subcommand** under `src/command/`.
- **Typed identifiers**: parse user-supplied references into domain types
  early; the rest of the command works on typed values, not raw strings.
- **Report actual results**: a command reports what happened, not an echo
  of its input. Operations return enough data to build accurate output.
- **Exit codes**: follow `quality-rust-exit_codes.md` — usage errors,
  data errors, and I/O errors map to distinct, documented codes.
- **Output**: structured data goes through the shared output trait so
  `--format json` and the plain table render from one source.
