# Grimoire CLI Commands — Quick Reference

Concise index of `grim` CLI commands. Implementation lives under
`src/command/` — read the source for return types, call sites, and report
column formats.

Index of shipped `grim` subcommands — keep in sync with `src/command/`
(one file per subcommand) and `docs/src/commands.md`.

## Command Surface

| Command | Purpose |
|---------|---------|
| `grim init` | Write a fresh `grimoire.toml` in the current directory; `--registry <ref>` seeds the default `[[registries]]` entry |
| `grim add [--kind …] [--name …] [--no-install] [--force] [--allow-hooks] <ref>` | Declare a skill/rule/agent/mcp/hook/bundle in `grimoire.toml`, pin it in the lock immediately, and (by default) materialize just that entry into the detected clients; `--no-install` stops at declare + lock; `--force` overwrites a locally modified artifact / untracked destination with `grim install --force` semantics (inert with `--no-install`). A hook declares and locks normally even with the feature flag off — the install half skips with a warning and `status` reads `gated`; the kind-inference path deliberately carries **no** flag check, so flipping the flag never requires re-running `add` |
| `grim lock` | Resolve floating tags in `grimoire.toml` to digests and write `grimoire.lock` (after hand-edits; `add` locks what it declares) |
| `grim config get\|set [--dry-run]\|unset\|list <key>` | Read and write `grimoire.toml` settings (`[options]`, `[options.tui]`, `[options.vendors.<name>]`) and registry fields via dotted keys; `list` dumps explicitly-set values for the active scope (never merged across scopes); `list [--all]` lists every supported key incl. unset, with JSON items carrying type/title/description/default metadata. `set --dry-run` validates and reports (report gains always-present `dry_run`) without acquiring the write lock or touching the file — same 64/65/79 error envelopes as a real `set`; no `unset --dry-run`. Exit codes: unset `get` → 1, unknown key → 64, bad value → 65. |
| `grim config registry add\|set\|rm\|use\|show\|list\|fields` | Registry lifecycle for `[[registries]]` entries: `add <alias> --oci\|--index <url> [--include <glob>]… [--exclude <glob>]… [--default] [--insecure]`, `set <alias>` (edit in place — same flags as `add` plus `--clear-include`/`--clear-exclude`/`--no-insecure`; applies only the flags given, keeps the entry's position, `--oci`/`--index` swaps the kind clearing the other side, `--default` cannot unset, `--insecure`/`--no-insecure` can; naming no field → 64), `rm <alias>`, `use <alias>` (at-most-one-default, clears prior), `show <alias>`, `list`. Alias not found (`set`/`rm`/`use`/`show`) or dup on `add` → 64. `--include`/`--exclude` are repeatable and **never comma-split** (a comma is glob alternation) — `add`/`set` are the only CLI paths writing a multi-pattern browse filter; `config set registry.<alias>.include` stores exactly one pattern, and `get` comma-joins for display and is not round-trippable. Clearing a list has two supported routes, both silent at any list length and both writing the emptied list as an absent key: `registry set --clear-include`/`--clear-exclude` (conflicts with its own list flag → 64) and `config unset registry.<alias>.include`. `registry set`'s write report carries the always-present `fields` array — one element per field written, in `RegistryField::ALL` order, `{field, action: set, value}` or `{field, action: cleared}` (no `value` key); `[]` on every other write verb. `show`/`list` carry always-present `include`/`exclude` arrays (`[]` unfiltered; plain cell is counts, `—` unfiltered) but **do not report `trust_hooks`** — it is addressable via the dotted `config get`/`set`/`list --all` route and documented by `fields`, yet absent from `show`, `list`, and `grim context`, so there is no single command answering "which registries are trusted for hooks" (documented as a gap in `docs/src/stability.md#limitations-hook-reporting`). `trust_hooks` is a **tri-state `Option<bool>`** — absent / `true` / `false` — and `write_config` must emit it whenever `Some`, *including* `false`: the hand-rolled serializer's emit-only-when-true convention would silently drop an authored opt-out and thereby re-arm a registry the user deliberately excluded. `fields` lists the 7 addressable per-registry field names (`oci`, `index`, `default`, `include`, `exclude`, `insecure`, `trust_hooks` — **append-only**, positions frozen) and their static type/title/description metadata — no `Context`, no scope resolve, no lock, works with no `grimoire.toml` present (unlike every other `registry` verb) |
| `grim install [--allow-hooks]` | Materialize every locked artifact into the configured AI client(s); no positional — declare via `add`, scope clients via `--client`. Refuses to overwrite an untracked pre-existing destination (65) unless `--force`; adopts identical content into the record. **Hooks are the one kind declined on policy rather than capability**: a locked hook arms only past the `[options.experimental] hooks` flag *and* per-registry `trust_hooks`, otherwise `InstallOutcome::Skipped` + one warning naming the single cause, exit stays 0. `--allow-hooks` (also on `update`/`add`) grants trust **per invocation**, is never persisted, and does **not** enable the feature flag; an explicit `trust_hooks = false` beats it. Convergence derives its own client set from the hook-capable roster and ignores the caller's, so every command is idempotent and self-healing regardless of what it was asked to do — do **not** narrow it to the clients a command happened to touch |
| `grim status` | Report each declared artifact's state (installed, outdated, modified, plus the hook-only `gated`/`not-armed`/`untrusted`) with bundle provenance; a hook row carries the always-present `arming` array (`{client, cause, message, transient}`, sorted by client, `[]` = armed everywhere) whose `cause` is the closed kebab-case `HookArmingCause` set and is the field consumers branch on — never `message`. A hook armed via `--allow-hooks` reports `installed`, not `gated`: `hook_arming` consults the **dispatch table first** (`armed_pairs`, via `existing_root_token` so no key material is ever minted on a read path), because the table is the machine-local arming authority and is derived rather than recorded. Config alone would under-claim for every `--allow-hooks` run, which is the state every CI run is in. The two remaining trust decisions `registry-not-trusted` collapses (never-granted and an explicit `trust_hooks = false`) are one reported cause on purpose; giving the opt-out its own cause is tracked as issue #92; JSON items carry always-present `clients_missing`/`clients_extra` (configured-vs-recorded client drift, local only) and always-present `outputs_pending` (`[{client, path}]`, sorted by client; materialization drift: what `grim install` would write now that the record does not cover — two causes, a new client or a layout move; a deleted file is **not** one of them, it reads `state: missing`; reported under autodetect too, since it asks what install would do rather than what was configured; never moves `state`, never affects the exit code; derived from `install::expected_outputs`, the same seam the installer's no-op check uses). `--check` (network, opt-in) adds a live catalog load populating `deprecated`/`replaced_by`, plus a fresh per-artifact re-resolution populating `update_available`; top-level `checked` gates all three — `false` forces them `null` on every item |
| `grim context` | Read-only introspection of the resolved invocation context: scope, config/lock/state paths (+ existence), effective client set (names only), registry browse set, default registry, offline (+ source). `registries[]` carries always-present `include`/`exclude` browse-filter patterns (`[]` unfiltered, and `[]` for every entry under `--registry`) plus an always-present `insecure` bool — the **authored** `[[registries]]` field, not the effective transport (a host reached over HTTP via the loopback default or `GRIM_INSECURE_REGISTRIES` still reports `false`), so it and `config get registry.<alias>.insecure` always agree **except under `--registry`**, whose synthesized entries carry no authored fields and report `false` for every row — a statement about the browse set only, since `--registry` never narrows the plain-HTTP transport set; plain row appends `, insecure` only when set, then `, N include, M exclude` counts, both omitted entirely when unset/unfiltered. Exits 79 outside a project without `--global` |
| `grim search [query]` | Substring search over the registry catalog (repo, summary, description, keywords); empty query lists all. Each source's `include`/`exclude` browse filter narrows the rendered rows at read time (`CatalogScope::Browse`) — the shared catalog cache is never narrowed, `--registry` browses unfiltered, and `grim status --check` uses `Complete` and is never filtered. A mis-aimed-pattern warning logs `registry '<name>': filter admitted <M> of <N> repositories; patterns match either the repository path or the fully-qualified reference, and anchor at the candidate's first segment — see https://grimoire.rs/configuration.html#browse-filters` (warn only, exit stays 0) when a non-empty `include` admits nothing from a group that had rows — **only on the unqueried browse**: `<N>` is post-query rows, so under `grim search <query>` the warning is silent (indistinguishable from a deliberate search for a hidden term). A non-empty `exclude` that removes nothing, and an exclude-only filter that empties a source, both stay silent. The 500-repo `MAX_CATALOG_REPOS` cap is applied at build time, **before** the filter — a narrow filter can never widen the window, and `truncated` keeps reporting build-time truncation verbatim |
| `grim fetch <ref> [--vendor …] [--path …] [--description] [--digest-only] [--out <dir>]` | Print an artifact's content without installing (CLI port of the MCP `grim_fetch` tool). `--description` fetches the repository companion (README, logo, CHANGELOG) instead of the artifact; `--out <dir>` unpacks that companion tree (only valid with `--description`). `--digest-only` resolves the reference to a digest and reports `{ref, digest}` **without downloading the manifest or any blob** — the cheap cache-freshness probe `grimoire-vscode` builds on; it composes with `--description` to probe the companion tag, and rejects `--vendor`/`--path`/`--out` (64). Plain = raw payload (pipe-able, no trailing newline; warnings on stderr); JSON = full fetch report. Never truncates a printed payload (MCP keeps its 256 KiB doc cap). Two download ceilings instead: the declared layer size is checked against the 8 MiB limit before download, and that same declared size then bounds the actual streamed bytes — a registry serving more than it declared aborts mid-transfer into a data error (65) rather than a silent truncation |
| `grim describe <ref>` | Report an artifact's manifest-level metadata — kind, curated + verbatim annotations, tags, `has_description` — **without** downloading its content. Single-object report; every field always present, `kind` null for a foreign manifest. CLI twin of the MCP `grim_describe` tool |
| `grim tui` | Interactive catalog browser with live install state (flat list / tree toggle) |
| `grim update [names…]` | Re-resolve floating tags, roll the lock forward, re-materialize what changed **through the same integrity gate as `install`** — a new pin overwrites freely, but a locally-modified artifact is refused (65) until `--force` (changed in 0.13.0; it used to force unconditionally); prunes clean orphans that dropped out of the lock, and reaps a dropped client's outputs when `[options].clients` narrows (`reaped_clients`/`kept_modified_clients` on the JSON row; `--force` reaps a locally-modified one too). No names = everything; names are config binding names, not refs |
| `grim remove <kind> <name>` | Undeclare an artifact (config + lock only; files left on disk). `<kind>` accepts `hook` |
| `grim uninstall [--force] <kind> <name>` | Full inverse of install: delete files, drop the install record, undeclare (config + lock). `<kind>` accepts `hook`, whose inverse also reaps the dispatch row **and** the client registration. Shared seam reused by the TUI delete action. **Exception:** an artifact a declared bundle still provides keeps its files (a directly-declared one degrades to `remove`; a bundle-only member is a no-op — remove the bundle to remove it). A managed MCP config entry that drifted from the recorded value is refused pre-flight (65, `reason: modified`, forceable) so nothing is half-removed; `--force` removes it. File outputs are deleted regardless of the flag |
| `grim build <path>` | Validate and pack a local skill/rule/agent/mcp/hook/bundle without pushing (release dry run). `--kind` accepts `hook` — **appended** to a frozen value set, never inserted. Path inference tests `hook.toml` **before** `SKILL.md` (both require `is_dir()`), so a hook directory needs no flag. Hook-specific build refusals (exit 65): a `matcher` outside `MATCHER_ALLOWED` / over `MATCHER_MAX_BYTES`; a handler whose `argv[0]` or `command` first token resolves to a payload-relative file (an OCI-fetched payload arrives `0o644`, so the exec bit is never load-bearing); a `policy` or vendor-override value using a TOML datetime / local-date / local-time, which the `serde_json::Value` model cannot re-emit without leaking a private sentinel; and a `ClientTarget::ALL` name used as anything but a vendor override |
| `grim release <path> <ref>` | Push a single artifact to a registry (validate, pack, push with cascade tags); `--push-registry <host[/prefix]>` pushes to a deviating endpoint while every baked/reported name keeps the reference's registry (the pull name; malformed value → 65), report gains always-present `pushed_to` (null when inactive) |
| `grim publish` | Batch-release all packages declared in a `publish.toml` manifest; validates whole manifest before any push; fixed kind order (skills → rules → agents → mcp → **hooks** → bundles — hooks appended after `mcp`, before `bundles`, so a bundle declaring a hook member finds it pushed; no existing kind's relative position moved), conventional hook source path `hooks/{name}/`, skip-existing by default. Optional manifest `push_registry` / `--push-registry` flag (flag wins) splits the push endpoint from the pull-named manifest `registry` (references, source fallback, pinned member ids, announce pointers, report `ref` all stay pull-named; per-entry `pushed_to` reports the push side) |
| `grim login [<registry>]` | Authenticate to a registry; store the credential via the docker-compatible credential store (helper or, with `--allow-insecure-store`, plaintext). Verifies the credential against the registry **before** storing by default (`/v2/` ping + challenge answer, scope-less): rejected → 80 nothing stored, unreachable/5xx/429 → 69 nothing stored, anonymous registry → 0 stored (`verification: no-auth-required`). `--no-verify` skips (store-only, `verification: skipped`); offline skips silently with a warning unless `--verify` is explicit → 81 |
| `grim logout [<registry>]` | Remove a stored registry credential (idempotent — exits 0 when nothing is stored) |
| `grim schema --kind <config\|publish\|lock\|mcp\|hook>` | Print the JSON Schema for `grimoire.toml`, `publish.toml`, `grimoire.lock`, the MCP descriptor (`mcp/<name>.toml`), or the hook manifest (`hook.toml`) to stdout (generated from the real parse structs); emits a document, not a `Printable` report. The clap `about` string enumerates all five (`grimoire.toml, publish.toml, grimoire.lock, mcp/<name>.toml, or hook.toml`) — a ⚠ note here claiming it omits `mcp` and `hook` was itself stale and is removed |
| `grim completions <shell>` | Print a `clap_complete`-generated completion script (`bash`, `elvish`, `fish`, `powershell`, `zsh`) to stdout; no eval hook, no shell auto-detect. Missing/unrecognized `<shell>` → 64. Document emitter, not a `Printable` report |
| `grim mcp [--allow-writes]` | Run a local STDIO Model Context Protocol server (rmcp SDK). Long-running, `Printable`-exempt (returns `ExitCode` directly, like `tui`/`schema`); stdout is the JSON-RPC channel. Read tools (`grim_search`, `grim_status`, `grim_fetch`) always on; the write tool `grim_render` gated behind `--allow-writes` (rmcp `disable_route`: hidden + rejected). Scope per tool call (`global`/`config`/`workspace` args; precedence in that order, default cwd walk-up) — launch scope flags removed, `--global`/`--config` exit 64 |
| `grim hook list` | List declared hooks with tier, events, and per-client arming state. Ordinary scope-resolving `Printable` report (`{artifact, id, tier, events, state, arming}`, one item per `[[hooks]]` entry, `arming` nested not flattened). Verdicts must come from `status.rs`'s `hook_arming` seam, never a second derivation of the same gates. The `[[hooks]]` entries come from the artifact's **materialized payload**, whose directory is derived from `$GRIM_HOME` and the resolved scope (`hook_dispatch::payload_dir`), never from the install record (SEC-1). A gated hook is skipped before its blob is fetched (S-001), so it has no manifest to enumerate: that artifact contributes no items and one stderr **warning** naming it — degrade, never fail (I3), and never silence |
| `grim hook run --client <c> --event <e> --table <abs> --root <token>` | Dispatch armed hooks for one client event. **Not intended for direct invocation** — its caller is the launcher grim generates, the same "documented but not for you" framing `grim mcp` gets. Reads **only** the `--table` file: no scope resolution, no config, no `Context`, no env data root (source-level import ban, asserted in `src/command/hook/mod.rs`; `hook/list.rs` is the deliberate exemption). **Exits 0 on every path grim controls** — unknown event, unknown root token, relative `--table`, missing table, failed handler — because a client that fails closed on a non-zero hook exit must never be denied a tool call by grim's internals. `--table` must be absolute (a relative one would resolve against the client-spawned CWD, i.e. the workspace, making the table repo-plantable); `--client` and `--root` are lookup keys only, never trust inputs, and `--root` is never compared against the CWD |
| `grim --version` | Print the compiled version (clap built-in; no subcommand) |

Global flags (`src/cli/options.rs` `GlobalOptions`): `--format`,
`--color <auto|always|never>` (default `auto`; styles clap help/errors and
`--format json`; `auto` is TTY-gated and honors `NO_COLOR`/`CLICOLOR`/
`CLICOLOR_FORCE`/`TERM=dumb`, `always` overrides `NO_COLOR`),
`--progress <auto|json|none>` (experimental; NDJSON events on stderr),
`--offline`, `--log-level`, `--config <path>`, `--global`,
`--registry <ref>` (repeatable / comma-separated).

`login`/`logout` resolve the registry from the positional argument when
given: an argument matching a `[[registries]]` alias substitutes that
entry's locator, anything else is taken as a literal hostname. With no
argument, the resolved scope's registry set supplies the primary —
`--registry` flag > `[[registries]]` default > `GRIM_DEFAULT_REGISTRY` >
project then global `[options].default_registry` — the same
`resolve_registries` chain `add`/`search` use, with `--config`/`--global`
selecting the scope as they do for every other command. Config **is**
consulted on this path; `Context::default_registry()` is a superseded
accessor with no production caller, so do not cite it as evidence
otherwise. The built-in `ghcr.io/grimoire-rs` fallback is deliberately not
substituted here — storing or erasing a credential for a registry the user
never named is a silent surprise — so an otherwise-unresolved set exits 78.
A global config that fails to load is fatal for `login` (78) and degrades
for `logout`, which still recovers the alias map when the file parsed and
only validation failed.
They read and write the docker config at `$DOCKER_CONFIG/config.json`
(default `~/.docker/config.json`) — the same file the credential read path
consults — so credentials round-trip with `docker login`.

## Conventions (apply as commands land)

- **One file per subcommand** under `src/command/`.
- **Typed identifiers**: parse user-supplied references into domain types
  early; the rest of the command works on typed values, not raw strings.
- **Report actual results**: a command reports what happened, not an echo
  of its input. Operations return enough data to build accurate output.
- **Exit codes**: follow `quality-rust-exit_codes.md` — usage errors,
  data errors, and I/O errors map to distinct, documented codes.
- **Output**: structured data goes through the shared output trait so
  `--format json` and the plain table render from one source.
