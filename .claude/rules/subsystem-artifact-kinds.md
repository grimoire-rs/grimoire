# Artifact Kinds: Interfaces and Consumers

What every kind does on every interface, who reads those surfaces, and the sites a new kind or kind-facing field must reach. Kinds: `ArtifactKind::ALL` (`src/oci/artifact_kind.rs`) = skill, rule, agent, bundle, mcp, hook, settings, mod. Frozen contract (Principle 9): **a new kind is appended last everywhere and nothing is reordered** — `ALL`, schema enums, `_KIND_ORDER` (`test/src/helpers.py`), clap value sets, bundle and `requires` layer order (digested bytes).

## Consumers

Release order for a new kind or field: **indexer, then grim, then extension**. Checked against each repo's `main` on 2026-11-21.

| Repo | Reads | Writes | Where |
|---|---|---|---|
| `grimoire-rs/indexer` | `grim describe <ref>` JSON: `kind`, `summary`, `keywords`, `deprecated`, `replaced_by`, `requires`; never raw `com.grimoire.*` annotations, `serves` or `com.grimoire.mod.clients` | Index records: `kind`, `summary`, `keywords`, `replacedBy` and `replaced_by`, `deprecated`, `requires` | `src/enrich/index.ts` (`mapMeta`, `describe` call), `src/emit/records.ts` (field caps, `REQUIRES_KINDS`), `src/data/index.ts` (`KINDS`), `src/enrich/marketplace.ts` (`MEMBER_KINDS`) |
| `grimoire-rs/grimoire-vscode` (remote name; never write `grimoire-rs/vscode`) | `grim --format json` output of `search`, `fetch` (`--path`, `--vendor`), `describe`, `status`, `add --kind`, `remove`, `uninstall`, `update`, `install`, `lock`; `summary` and `keywords` nullable; no `serves`, no MCP | none (shells out) | `src/grim.ts` (argv builders ~973-1126), `src/webview/protocol.ts` (`ArtifactKind`) |

Neither lists `mod` yet (the indexer's lists stop at `settings`). `test/data/conformance/` is generated by the indexer (`scripts/gen-conformance.mjs`), never hand-edited. The tree carries rows of every kind, including `settings`, `mod` (with `serves`) and both successor spellings, generated at the indexer SHA in its `MANIFEST.json`; grim reads it in `src/catalog/conformance_tests.rs` and in the `test_search_from_the_indexer_tree` pytest column. Regeneration order: the indexer adds seed rows (`test/conformance/seed.mjs`), grim adopts the tree (replace every file except `README.md`, never hand-edit), grim releases, then the indexer moves `test/conformance/GRIM_REF` to that release.

Two further refusals sit outside the 13 columns and are not in the suite (last two rows).

Deciding line and consumer check per refusal (no ADR line decides any refusal except `grim_render` and mod `--vendor`; do not invent one):

- **hook, no summary/keywords** — no ADR line (user contract: `docs/src/content/docs/publishing.md:1222`). Indexer: `summary` copied only when non-null (`src/enrich/index.ts`, `mapMeta`), keywords default `[]`. Extension: `summary: string | null` (`src/grim.ts:71`).
- **bundle, mcp, settings: no file list, `--path` refused** — no ADR line (`src/fetch.rs` arms). Indexer: not read (it fetches `--description --digest-only`, `src/grim.ts:11`). Extension sends `--path` (`src/grim.ts:1017`); gating by kind not verified.
- **uninstall bundle exits 64** — no ADR line. Extension: handled, bundles route to `remove` (`src/grim.ts:1084`); indexer: not read.
- **mod `--vendor`** — `.agents/adr/adr_mod_artifact_kind.md` D13 (Fetch). Extension sends `--vendor` (`src/grim.ts:1020`), mod handling not verified; indexer: not read.
- **`grim_render` refuses mod** — `.agents/adr/adr_mod_artifact_kind.md:308` (D13; the gaps table row says the same). Neither consumer uses MCP. `grim_fetch` answers for a mod (`test_fetch_document`, `test_mod_fetch.py`).

## Site checklist (new kind or kind-facing field)

1. `ArtifactKind::ALL` append last, `all_index`, `subdir`, wire token — `src/oci/artifact_kind.rs`.
2. Annotations and read-back (`serves`-style fields) — `src/oci/annotations.rs`; manifest and layer layout — `src/oci/manifest.rs`, `src/oci/layer.rs`; kind manifest module (`src/oci/mod_manifest.rs`).
3. Bundle and `requires` members, `requires-features` — `src/oci/bundle.rs`, `src/oci/requires_decl.rs`, `src/oci/features.rs`.
4. Declaration table and `DesiredSet` — `src/config/declaration.rs`, `src/config/project_config.rs`; telemetry `declared_identifiers` — `src/telemetry/record.rs`.
5. Lock tables and effective set — `src/lock/grimoire_lock.rs`, `src/lock/effective_set.rs`, `src/lock/closure.rs`.
6. Index reader — `src/catalog/index_package.rs`, `index_source.rs`, `registry_catalog.rs`, `search_match.rs`; search report — `src/api/search_report.rs`; `grim search --kind` values.
7. Fetch arm — `src/fetch.rs`; MCP tools — `src/mcp/render.rs`, `src/mcp/fetch.rs`, `src/mcp/describe.rs`.
8. Install phase and report rows — `src/install/installer.rs`, `src/install/expected_outputs.rs`, the kind's phase (`src/install/mod_phase.rs`); status — `src/api/status_report.rs`, `src/command/status.rs`; commands `add`, `build`, `release`, `publish`, `remove`, `uninstall`, `update` under `src/command/`.
9. `grim schema --kind` and clap help text — `src/command/schema.rs`, `src/main.rs` (`Schema` about); `publish.toml` order and `config_keys`.
10. Docs pages that list kinds — `docs/src/content/docs/{artifacts,concepts,commands,json-interface,publishing}.md` plus the kind's own page; stability and upgrade notes.
11. Catalog skills — `catalog/skills/grim-usage`, `catalog/skills/grim-authoring` (`catalog/README.md` drift review).
12. Rule lists — `.claude/rules/subsystem-cli-commands.md` rows `add`, `build`, `publish`, `schema`; `arch-principles.md` annotation row; this rule.
13. Consumers, in order: indexer lists (`src/data/index.ts`, `src/emit/records.ts`, `src/enrich/marketplace.ts`), regenerate `test/data/conformance/` in the indexer and adopt it in grim, then grim release, then the indexer moves `GRIM_REF`, then extension (`src/grim.ts`, `src/webview/protocol.ts`).
14. Tests: add the kind to `KINDS` and every table in `test/tests/test_kind_interfaces.py`; `_KIND_ORDER` in `test/src/helpers.py`.

## Tests

`test/tests/test_kind_interfaces.py` is driven by one `KINDS` list pinned to the binary (`test_kinds_list_matches_the_binary`): a new kind fails until every table says what it does, and nothing skips. Per-kind depth: `test_mod_fetch.py`, `test_mod_lifecycle.py`, `test_mod_publish.py`, `test_mod_build.py`, `test_mod_install.py`, `test_mod_status.py`, `test_settings_*.py`, `test_hook*.py`, `test_agents.py`, `test_bundles.py`, `test_mcp*.py`; the skill and rule paths sit in `test_install.py` and `test_fetch.py`.
