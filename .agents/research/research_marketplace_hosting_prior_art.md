Coexistence evidence (Q1 last part):
- Stated fallback chains: Copilot (`.github/plugin` then `.claude-plugin`), Codex (`.agents/plugins` then `.claude-plugin`), Droid (`.factory-plugin` then `.claude-plugin`). A repo carrying only `.claude-plugin/marketplace.json` is therefore read by Claude, Copilot CLI, Codex, Droid, Junie. A repo carrying each harness's own file is, per the stated order, read by each through its own file first. Whether a fallback file is ignored (not merged) once the primary exists is implied by "fallback" but not stated in any doc.
- Working in-the-wild examples of coexisting files: [S2] `.claude-plugin/marketplace.json` + `.agents/plugins/marketplace.json` at one repo root (Claude + Codex), one vendored `plugins/<name>/` tree; [S1] `.claude-plugin/` + `.cursor-plugin/` generated from one config. Neither claims tested isolation; both are secondary.
- Not found: any vendor doc that says "we ignore other vendors' marketplace files", and any Cursor/Claude doc that says they read `.github/plugin/` or `.agents/plugins/`.

Redundancy signal: where skills are slash-invocable (Claude, Copilot, Cursor, Droid, VS Code) a command wrapping a skill duplicates its slash entry, and a same-named command shadows the skill in Droid. ## Notes

- Junie and Qoder and Droid each accept a bare HTTPS `marketplace.json`; only Claude documents what breaks (relative paths). Whether Junie/Qoder/Droid resolve relative `source` against the JSON's URL, or reject them, is undocumented. Practical consequence for static Pages hosting: Claude requires self-contained (non-relative) entry sources; the others are unknown.
- A Pages-hosted `marketplace.json` for Claude therefore needs each entry to be `archive` (zip + sha256), `github`/`url`/`git-subdir`, or `npm`. `archive` needs no git at the user's end (C3).
- Copilot CLI's `.claude-plugin` fallback, Codex's legacy `.claude-plugin`, Droid's fallback and Junie's dual support mean one Claude-format file serves five harnesses at file level; per-harness files exist to carry harness-specific `source` shapes (Codex `source: local|git-subdir|npm`, Cursor `pluginRoot`).
- Entry shape differs even with the same filename: Codex `source` is an object with `"source":"local","path"`; Claude/Copilot/Cursor accept a plain relative string.
- Update semantics diverge: Claude compares computed version strings (manifest > entry > SHA); Droid tracks commits and ignores manifest `version`; Gemini release installs ignore manifest `version`; Qoder compares semver; Codex/Copilot/Cursor/Junie undocumented. A single generated `version` per plugin satisfies Claude and Qoder; SHA-only harnesses ignore it.
- Same plugin name in two marketplaces: Claude's isolation key is the marketplace `name` (docs warn a duplicate marketplace name cannot be registered twice); [S1] warns a colliding marketplace name "shadows or strands" the first's plugins. Codex's cache path also embeds the marketplace name.
- Gemini CLI page header states "Gemini CLI was replaced by Antigravity CLI on June 18th, 2026" for unpaid tier users (M3); Antigravity marketplace/plugin surface is outside this lane (see prior matrix).
- Kilo's fetched "plugins" are executable TS/JS modules (npm or git), not Agent Plugins; Kilo items are hosted centrally, not from a user repo.
