## Direct Answer

Claude.ai / Claude Desktop / Cowork accept **three separate file-upload formats**, each solving a different problem, and none of them is Claude Code's own plugin marketplace mechanism:

1. **Plugin upload** (`Customize > Plugins > Add > Upload plugin`): a `.zip` or `.plugin` of a plugin folder containing `.claude-plugin/plugin.json` at the archive root (zipping either the folder itself or its contents both work). Limits: 200 MB / 5,000 files per plugin; up to 25 self-added marketplaces per account per org. Individual users can upload for themselves; org admins upload the same way at **Organization settings > Plugins & skills > Add > Upload a plugin**, then set that plugin's **Default access** (Not available / Available to install / Installed by default / Required) to roll it out org-wide — no separate "publish" step needed once it's admin-uploaded.
2. **Skill upload** (`Customize > Skills > Add`, or the org-admin equivalent): a `.zip` with the skill folder as the archive root (not nested), one skill per zip, folder name must match the skill name, `SKILL.md` required. Stated limit: 30 MB uncompressed (per Anthropic's Skills docs on `platform.claude.com`; the claude.ai upload help article only says "ZIP file exceeds size limits" without repeating the number — likely the same ceiling, not independently confirmed for the claude.ai upload path specifically).
3. **MCP Bundle / desktop extension** (`.mcpb`, née `.dxt`): installed only in Claude Desktop, via **Settings > Extensions**, drag-and-drop the `.mcpb` file → preview → **Install**. Not uploadable through claude.ai web.

Component support is surface-dependent, not upload-format-dependent: **skills and remote (URL) MCP connectors work in chat; agents, hooks, and local/command MCP servers (including `.mcpb`-packaged ones) additionally work in Cowork and Claude Code; LSP servers, output styles, themes, and top-level `bin/` executables are Claude-Code-only** (chat and Cowork ignore them, and a top-level `bin/` makes chat/Cowork refuse the whole plugin).

The phrase **"a marketplace made of a member's own claude.ai uploads"** appears in `code.claude.com/docs/en/plugins/org`, in the section on allowlisting marketplaces hosted on claude.ai via a `hostPattern` matching `claude.ai`. It means: when an org sets `strictKnownMarketplaces` with a `hostPattern` entry for `claude.ai`, that allowlist entry admits the org's own claude.ai-hosted marketplaces and Anthropic's default ones, but it does **not** admit a synthetic marketplace that Claude Code derives from an individual member's personal claude.ai uploads (nor one whose scope claude.ai didn't explicitly state) — i.e. Claude Code's managed-settings allowlist cannot be used to trust "whatever a given user happens to have uploaded to their own account" as if it were an org-vetted source.

Desktop can add a plugin marketplace by URL/repo shorthand through the same `Customize > Plugins > Add > Add marketplace` UI used on the web (GitHub/GitHub Enterprise repos, plus public GitLab and Bitbucket repos) — this is chat/Cowork-scope, UI-driven (paste a URL, no git CLI), so usable by a non-technical user, though it does require understanding what a "plugin marketplace repository" is. This is distinct from Claude Code's own marketplace registration (`/plugin marketplace add`, or the Desktop app's **Code tab** plugin browser), which is a developer-facing, terminal-adjacent flow.

## Key findings

1. Plugin upload layout: zip either the plugin folder itself or its contents — both accepted, as long as the archive contains exactly one `.claude-plugin/plugin.json`. Limits: 200 MB and 5,000 files per plugin (also the largest single file **Upload plugin** accepts is 200 MB); up to 25 self-added marketplaces per account per organization. — [claude.com/docs/plugins/platform-support](https://claude.com/docs/plugins/platform-support), [claude.com/docs/plugins/overview](https://claude.com/docs/plugins/overview)
2. Org admin path for making an uploaded plugin available org-wide is **Organization settings > Plugins & skills > Inventory**, upload via **Add > Upload a plugin**, then set the row's **Default access**: `Not available` (hidden) / `Available to install` (opt-in, shows under Discover) / `Installed by default` (on for everyone, can disable) / `Required` (on, can't be removed). On Enterprise, this can be further scoped **per user group**, with group settings overriding org-wide ones. — [claude.com/docs/plugins/admin](https://claude.com/docs/plugins/admin)
3. Component support is the load-bearing table (`claude.com/docs/plugins/platform-support`): Skills load everywhere. Commands load as a skill in chat but as a literal `/plugin:command` in Cowork/Claude Code. **Agents and hooks are ignored in chat**, load in Cowork and Claude Code. **Remote MCP (http/sse) works in chat**; **local/command-based MCP servers (including `.mcpb`) are ignored in chat**, load in Cowork only when the session runs on the user's own machine, and load unconditionally in Claude Code. `${user_config.*}`-templated MCP servers are ignored in chat, ignored in Cowork when no default is set (Cowork never prompts), and prompt interactively in Claude Code. **LSP servers, output styles, themes, and plugin `settings` are Claude-Code-only** and ignored elsewhere; a top-level `bin/` directory makes chat and Cowork refuse to install the plugin at all (Claude Code still loads it).
4. Skill upload layout confirmed from Anthropic's own help article: the zip's root must **be** the skill folder (not files loose at the zip root, and not the skill folder nested one level further down), and the **folder name must match the skill's `name`**. Required file: `SKILL.md` (root of that folder). One skill per zip — no documented multi-skill-per-zip upload path in the claude.ai UI. — [support.claude.com/en/articles/12512198](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills)
5. The 30 MB figure is documented as "total upload size must be under 30 MB (uncompressed)" on Anthropic's Skills guide (`platform.claude.com`), which is written primarily for the Skills API/Agent SDK context. The claude.ai/Claude-Desktop help article on creating custom skills lists "ZIP file exceeds size limits" as a failure mode but does not itself restate a number, so the 30 MB ceiling for the **claude.ai upload UI** specifically is inferred, not independently confirmed by a claude.ai-scoped primary source. — [support.claude.com/en/articles/12512198](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills), [platform.claude.com/docs/en/build-with-claude/skills-guide](https://platform.claude.com/docs/en/build-with-claude/skills-guide)
6. MCP Bundle (`.mcpb`, formerly `.dxt` Desktop Extensions) install path in Claude Desktop is **Settings > Extensions**, drag the `.mcpb` file onto the page, preview, **Install**, confirm. This only works in the desktop app, signed in to claude.ai; the manifest format itself (`manifest.json`) is documented upstream in the now-independent `modelcontextprotocol/mcpb` project, not duplicated in Anthropic's own docs beyond a pointer. Required manifest fields per the MCPB spec: `manifest_version`, `name`, `version`, `description`, `author`, and a `server` object (`type`: `node`/`python`/`binary`/`uv`, `entry_point`, `mcp_config` with `command`/`args`/`env`, supporting `${__dirname}` and `${user_config.KEY}` substitution). The manifest can describe a **locally launched command** (e.g. an `npx`/`uvx`-style invocation via `mcp_config.command`+`args`) — the spec source did not surface an explicit remote-HTTP-server manifest shape distinct from the command-launch shape; treat "does `.mcpb` support a pure remote/HTTP server with no local process" as **undocumented** in what was retrieved (Anthropic's own connectors doc frames `.mcpb`/desktop extensions specifically as the *local*-server option, contrasted with "add a connector by URL" for remote servers — implying `.mcpb` is for the local-launch case, not a substitute for the URL-based remote-connector flow). — [claude.com/docs/connectors/custom/add-unlisted](https://claude.com/docs/connectors/custom/add-unlisted), [github.com/modelcontextprotocol/mcpb/blob/main/MANIFEST.md](https://github.com/modelcontextprotocol/mcpb/blob/main/MANIFEST.md)
7. `.mcpb` is also a valid *component inside a plugin*, not just a standalone Desktop install: the platform-support table lists "Local MCP server, a command the app starts, **including `.mcpb` bundles**" as a plugin component, ignored in chat, loaded in Cowork (only when the session runs on the user's own computer) and in Claude Code. — [claude.com/docs/plugins/platform-support](https://claude.com/docs/plugins/platform-support)
8. Desktop's plugin-marketplace-by-URL flow for chat/Cowork uses the same UI as claude.ai web (`Customize > Plugins > Add > Add marketplace`), accepting a GitHub/GitHub Enterprise repo, or a public GitLab/Bitbucket repo, by URL or `owner/repo` shorthand — a paste-a-URL flow with no git tooling required, so it is usable by a non-technical user (though the concept of "a plugin marketplace repository" itself presumes some familiarity). This is separate from Desktop's **Code tab** plugin browser (`+ > Plugins > Add plugin`), which installs Claude-Code-scoped plugins and is a different, more developer-oriented surface reachable only from local/SSH Code-tab sessions (not available in Desktop's cloud sessions). — [claude.com/docs/plugins/overview](https://claude.com/docs/plugins/overview), [code.claude.com/docs/en/plugins/install](https://code.claude.com/docs/en/plugins/install)
9. Individual (non-admin, non-Team/Enterprise) users on Pro/Max/Free can also create and upload their own plugins/skills to their personal account (`Customize > Plugins > Add > Upload plugin`, `Create a plugin`, `Create with Claude`); on Team/Enterprise this is gated by the org's **Policy > User-created skills** switch, which — when off — hides all of Upload/Create plugin options from members entirely.

## negative:

- No claude.ai-scoped (as opposed to platform.claude.com API-docs-scoped) primary source was found stating the skill-zip size limit as a number; the 30 MB figure is sourced from the Skills API guide, not a help-center article about the claude.ai upload UI itself.
- No documented file-count limit for skill zips was found in any primary Anthropic source (a third-party GitHub discussion reported a ~200-file rejection message, but this was not corroborated by an Anthropic doc and is excluded from Key findings as non-primary).
- No primary-source confirmation that the claude.ai/Desktop plugin or skill upload UI enforces the folder-name-must-match-skill-name rule identically for **plugin**-embedded skills (`skills/<name>/SKILL.md` inside a plugin zip) as it does for a standalone skill upload — the "folder name must match" rule was documented only for the standalone skill-upload flow.
- Whether `.mcpb`'s manifest format has a documented, spec-level way to declare a purely remote/HTTP MCP server (no local process at all) could not be confirmed from the MANIFEST.md excerpt retrieved; Anthropic's own docs treat `.mcpb`/desktop extensions and "connector by URL" as two distinct, non-overlapping paths, which is suggestive but not a direct statement that MCPB structurally cannot express a remote server.
- No admin-console screen or setting was found that lets an org "allowlist" a specific member's personal claude.ai-uploaded plugin as a trusted Claude Code managed-settings source — the `hostPattern: claude.ai` allowlist entry explicitly does **not** cover this case, and no alternate mechanism for it surfaced in `plugins/org.md`.

## leads:

- If harness-native-marketplaces work wants to target claude.ai/Desktop as an export format, the natural artifact shape is a **plugin zip** (`.claude-plugin/plugin.json` at zip root, optional `skills/`, `agents/`, `commands/`, `hooks/hooks.json`), since that is the one upload format that (a) claude.ai/Desktop/Cowork/Claude Code all load, if only a subset of components each, and (b) has documented, generous limits (200 MB / 5,000 files) versus the much tighter 30 MB skill-only path.
- `claude.com/docs/plugins/build` ("Plugin structure and testing") was not fetched in this pass and would be the next stop for the exact `.claude-plugin/plugin.json` schema and the "bundle a connector with its skill" pattern referenced from the platform-support table.
- `claude.com/docs/plugins/org-sync` (repository requirements organization sync enforces, including the top-level `bin/` rejection) was referenced but not fetched directly — worth a follow-up read if planning an org-distributed marketplace repo.
- `github.com/modelcontextprotocol/mcpb` (full MANIFEST.md, plus the `@anthropic-ai/mcpb` CLI: `init`/`pack`) is the canonical spec home now that MCPB moved out of Anthropic-only docs into the open MCP project; re-check `manifest_version` (currently 0.3) before relying on exact field names, since it is external to Anthropic and evolves independently of Claude's own release cadence.
