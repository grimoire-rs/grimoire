## Direct Answer

1. ocx already recorded answers for almost every ingest question except three: licence or redistribution consent (nothing recorded), takedown (only a complaint-driven namespace dispute path), and "upstream content changed under an unchanged version" (no explicit decision; behaviour is "skip, because the version exists").
2. The ocx answer to "one upstream, several packages" is one `mirror.yml` per package and several specs per repository, never one multi-asset spec (`ocx-mirror/.claude/artifacts/plan_mirror_capability_cut.md:73-76,140-142`).
3. ocx-mirror is a separate repository and binary today, discovered by `ocx mirror` as a PATH plugin, linking ocx crates through a git submodule and shelling out to `ocx package push` on every leg except one legacy leg. The original ADR said otherwise (workspace crate, library calls only), and was superseded in practice in 2026-05 and 2026-06.
4. The ocx mirror signs only what it builds, with its own identity, carries upstream signatures verbatim on registry copies, and verifies nothing at copy time. The clients verify against an index-declared `publishers` list; "a mirror is never a trust point".
5. The grimoire contracts are mostly compatible or silent. Real conflicts: ocx's vendor-identity namespaces versus grimoire's "namespace = announcing forge identity" with a live `owner.id` check; ocx's `upstream` attribution object has no grimoire index field; grimoire `grim publish` rejects `+build` and non-strict-semver entry versions; and the trust ADR names itself as the revision point when signatures arrive.
6. Grimoire never considered an import direction. Every "inverse" in grimoire records means something else (see Part 3).

### 1.2 The `mirror.yml` spec

**D-spec-1. One spec file per package.** Decision: one YAML per package, `name`, `target`, `source`, `assets`/`variants`, `metadata`, `versions`, `cascade`, `verify`, `sign`, `annotations`, `announce`. Rejected: one file listing all packages ("different source configuration, asset patterns, and metadata; separate files are easier to review in PRs, owned by different teams") `[src: adr_ocx_mirror.md:1193-1197]`. Status: shipped; since extended to several specs per repository with `--spec` repeated `[src: mirror-yml.md:1470-1560; cli.md:107]`.

**D-spec-2. Source kinds.** Original: `github_release | url_index` with a `type:` discriminant (rejected: sibling keys per source, "ambiguity of two source-type keys") `[src: adr_ocx_mirror.md:1199-1203]`. Added by later records: `url_index.generator` (rejected: more Rust adapters, a `Source::Script` type, a declarative URL template DSL; chosen because "url_index already defines the right data shape") `[src: adr_mirror_source_generators.md:46-107]`; `pylock` and `pypi` `[src: mirror-yml.md:66-76]`; `cargo` proposed, not built. Unknown keys under `source:` are a hard parse failure `[src: mirror-yml.md:68]`.

**D-spec-3. Canonical internal form.** Every adapter yields a version string plus a flat map asset-name to URL (optionally a digest); platform resolution is one shared step using top-level `assets:` regexes. "Switch a mirror from url_index to github_release without touching `assets:`" `[src: adr_ocx_mirror.md:38-46,290]`. Rejected: asset patterns inside each source block (duplication, per-adapter resolvers) `[src: :1157-1161]`.

**D-spec-4. Asset selection.** All patterns apply; exactly one distinct asset per platform; zero = platform absent for that version, silent; two or more distinct = `Ambiguous` error, that version aborts. Rejected: first-match-wins (hides a wrong-binary mistake) `[src: adr_ocx_mirror.md:103-108,1163-1167]`. Current doc agrees `[src: mirror-yml.md:160-163]`.

**D-spec-5. Package name and target repository.** `name` is "used in logging only" `[src: adr_ocx_mirror.md:51]`; the physical destination is `target.registry` + `target.repository`, written out by the spec author, never derived from the upstream `owner/repo` `[src: mirror-yml.md:37-60]`. Slash segments never flattened (`ocx-contrib/bazelbuild/bazelisk`) `[src: mirror-yml.md:44]`. Owner ruling 2026-07-25: logical index name `ocx.sh/<vendor>/<package>` maps to physical `ghcr.io/ocx-contrib/<vendor>/<package>`; the mirror repo is named for the vendor (`mirror-<vendor>`) `[src: ocx/.claude/artifacts/design_spec_announce_initiative.md:116 (E-P4)]`. The logical `announce.package` is a separate required key "not derived from target.repository" `[src: mirror-yml.md:1295-1300]`. The first path segment of `target.repository` must equal the mirror repository's own owner, because `GITHUB_TOKEN` authorises only that owner's packages `[src: mirror-yml.md:50-52]`. Republishing under `ocx-contrib/*` with two segments (ocx-mirror#18) was explicitly out of the capability cut `[src: plan_mirror_capability_cut.md:43-50]`.

**D-spec-6. Upstream version to tag.**
- `github_release`: `tag_pattern` regex with named group `version` and optional `prerelease`; default `^v?(?P<version>\d+\.\d+\.\d+)(?:-(?P<prerelease>[0-9a-zA-Z]+))?$`. A tag that does not match is skipped with a warning. Drafts are always dropped, "not configurable", because they are unpublished `[src: adr_ocx_mirror.md:67-86,606; mirror-yml.md:85]`. Rejected: a `strip_tag_prefix` string (cannot handle `release/1.2.3`, `2024.03.11`) `[src: adr_ocx_mirror.md:1175-1179]`.
- Normalisation table: major-only is an error ("too ambiguous to pad"), `X.Y` pads to `X.Y.0`, `X.Y.Z+build` from the source is an error, prerelease token must be one `[0-9a-zA-Z]+` segment `[src: adr_ocx_mirror.md:418-432,1217-1221]`.
- Tag spelling shipped differs from the ADR. ADR: `X.Y.Z+{timestamp}` (`:134,438`). Shipped: `3.28.0_20260310142359`, prerelease `3.28.0-rc1_<ts>`, `build_timestamp: datetime|date|none` `[src: mirror-yml.md:830-853; ocx/.claude/artifacts/adr_cli_repo_split_template.md Decision item 5 "plain X.Y.Z_<TS> + cascade"]`. The reason for `_` is not written in the records read `[inf: OCI tag charset has no `+`]`.
- Variants: `variants:` gives each flavour a tag prefix (`slim-3.13.9`); `libc` flavours are `+libc.glibc` platform-key suffixes published as OCI `os.features`, "no `-musl` tag suffixes ever" `[src: mirror-yml.md:454-488,168-190; design_spec_announce_initiative.md:114 (E-P2)]`.
- PyPI: versions read from index filenames, PEP 440 prerelease detection, all-yanked versions dropped; first index that has the project wins, never merged across indexes (dependency-confusion guard) `[src: mirror-yml.md:222-270]`.

**D-spec-7. Upstream with no usable version.** Three recorded behaviours, no single "no version" decision: non-matching tag skipped with a warning (above); major-only, build-bearing or unparseable versions error or skip as in D-spec-6; **version translation is explicitly deferred**: "full version translation... is deferred. ... the escape hatch is straightforward: generate a url_index JSON with already-normalized version keys. For non-standard sources a small script ... is simpler than a general-purpose transformation DSL" `[src: adr_ocx_mirror.md:1119-1129]`. `version_map` and `tag_transform` were named and not designed `[src: same]`. Version bounds from a vendor channel pointer, resolved fail-closed (exit 69, no unbounded fallback) `[src: mirror-yml.md:762-828]`.

**D-spec-8. Version window and pacing.** `versions.min` inclusive, `max` exclusive for bare strings, `new_per_run` throttles rate, never caps the total (rejected: a permanent `limit`), `backfill: newest_first|oldest_first` `[src: mirror-yml.md:736-760; adr_ocx_mirror.md:1187-1191]`. `skip_prereleases` (rejected: `include_prereleases`, because all booleans default false) `[src: adr_ocx_mirror.md:1223-1225]`.

### 1.3 One upstream, several packages

- Decision (owner): **three separate packages, one spec per binary**, for bazelbuild/buildtools; multi-asset-per-platform "unnecessary", so the resolver's `Ambiguous` arm is never reached. What it required: several specs in one repository `[src: plan_mirror_capability_cut.md:73-80,140-142]`. Repos are grouped by upstream GitHub org (`mirror-bazelbuild` holds bazelisk, buildifier, buildozer, unused-deps, bazel) `[src: :143-146]`.
- Alternative rejected: one spec emitting several binaries ("layer reuse buys nothing across three unrelated static binaries"; asset resolver would error) `[src: :140-142, capability table :61-66]`.
- Flavours of one tool (PGO, slim) use `variants:` inside one spec `[src: mirror-yml.md:454-488]`.
- Multi-spec repository rules: each spec its own generated workflows; `script:` resolves from repo root, `catalog:` from the spec's own directory `[src: mirror-yml.md:1548-1590]`.
- A package that does not run on its own (bazel without a JDK) is not mirrored; the bundled-JRE build is, because an undeclared runtime dependency would ship a package that fails at run time `[src: plan_mirror_capability_cut.md:143-146]`.

### 1.4 Update detection, scheduling, idempotency

- **Detection:** one `list_tags` call, set-difference against upstream versions, no local state file (`adr_ocx_mirror.md:709-731`, "Stateless renotify" reaffirmed `adr_ocx_mirror_test_pipeline.md` D11 row). Rejected: per-tag manifest HEAD (N calls). A partially published version (tag exists, a platform missing) is repaired: always-on platform-completeness check, `--skip-platform-check` to opt out `[src: adr_ocx_mirror.md:733-741,1239-1243]`. Today surfaced as plan kinds `new`, `backfill-partial`, `metadata-drift` `[src: plan-json.md:106-123; cli.md:139]`.
- **Scheduling:** the tool has no daemon. `pipeline generate ci` renders `mirror.yml` (discover, prepare, test, push, notify), `describe.yml`, `patch.yml`, `cascade.yml`, `verify-generated.yml`; `versions.poll_interval` is a cron string passed through; `cascade.schedule` and `announce.schedule` are separate crons, each deliberately different to avoid the shared concurrency group `[src: getting-started.md:85-117; mirror-yml.md:713-727,758,1366-1378]`. Principle: every capability is one pasteable command, rendered GitHub workflows are a convenience `[src: ocx-mirror/AGENTS.md:19-25]`. Rejected: a custom GitHub Action ("deferred until the CLI stabilizes") `[src: adr_ocx_mirror.md:1227-1231]`.
- **Re-run when the tag exists:** skip. `sync` "filter[s] against tags already published" `[src: cli.md:22]`; summary statuses `succeeded|failed|skipped` `[src: cli.md:375]`; announce reports `nothing_to_announce` and makes no call when nothing was pushed `[src: mirror-yml.md:1311-1313,1334]`. `--version V` mirrors exactly the listed versions `[src: cli.md:34]`; whether it still bypasses the already-mirrored check (ADR `:741`) was not verified in code `[inf]`.
- **Unique-tag guard:** with `datetime`/`date` each build lands under its own never-re-pointed `X.Y.Z_<ts>` tag so a lock pinned `@sha256:` survives registry GC; `build_timestamp: none` is documented as safe only where a version is "never re-published" `[src: mirror-yml.md:830-853]`.
- **Upstream content changed under the same version:** no decision recorded. What exists: digest checks reject bytes that differ from the digest the source declares (`verify.github_asset_digest`, `verify.url_index_digest`, `verify.checksums_file`; mismatch fails that tile, exit 1, nothing published); GitHub digest check was dead code before 0.6.2 `[src: mirror-yml.md:855-905]`. The ADR's risk table names a compromised upstream asset and mitigates it only by those digests `[src: adr_ocx_mirror.md:1291]`. SLSA or cosign verification of upstream was explicitly not required ("adoption remains low... may be added as an optional layer later") `[src: :1237]`.
- **Metadata-only repair:** `pipeline patch --metadata-only` re-emits manifests referencing published layers by digest, idempotent by config-blob digest (rejected: a patch ledger, a stored range in `mirror.yml`); "patching evicts nothing", prior digests and the canonical `sha256.<hex>` tag survive; it chains into announce `[src: plan_mirror_capability_cut.md:9-20,112-135; cli.md:293-321]`.
- **Retry:** `max_retries` is push-only, exit 75 only, backoff 1s doubling to 30s plus jitter; `max_pushes` removed `[src: adr_ocx_mirror.md:202-213]`.

### 1.5 Where the tool lives and how it calls the main CLI

Three stacked records, each superseding part of the one before.
1. `adr_ocx_mirror.md` (2026-03): **separate binary crate in the ocx workspace, not a subcommand, not a separate repository**; reasons: dependency divergence (reqwest, serde_yml, regex), distribution scope, release cadence, single responsibility. Rejected: subcommand (bloat), separate repository ("duplicates build infrastructure, harder to stay in sync with ocx_lib") `[src: :1077-1085,1139-1143]`. **Direct `ocx_lib` calls, not shell-outs**: faster, no PATH dependency, typed errors `[src: :826-836,1145-1149]`.
2. `ocx/.claude/artifacts/adr_cli_plugin_pattern.md` (2026-05-28): `ocx mirror` dispatches to a PATH binary `ocx-mirror` (git-style argv, name dropped), no manifest, no registry; built-ins always win `[src: `:Decision` 1-7]`. Priority was UX discovery and dogfood install (`ocx --global add ocx.sh/ocx/mirror`), not technical decoupling `[src: ocx/.claude/artifacts/research_plugin_architecture.md:123-131]`.
3. `adr_cli_repo_split_template.md` (2026-06-12): **separate repository**; the satellite vendors ocx as git submodule `external/ocx` and path-depends on ocx crates. Rejected: ocx workspace member from satellite submodule; publishing `ocx_lib` to crates.io ("pre-1.0 API churn", "publishes an API surface ocx does not want to stabilize") `[src: :35-70]`. Repeatable contract for later satellites (`ocx-mcp`, `ocx-dist`): crate shape, patch table, bump procedure, five CI workflows, registry layout `ocx/<name>`, independent semver, history via `git filter-repo` `[src: :80-120]`.
4. Present state: the mirror links ocx crates in-process for the legacy `package sync` leg and for classification helpers, and runs `ocx package push` as a **subprocess** for the archive leg, the env (pylock/pypi) leg and the patch leg `[src: adr_mirror_signing.md:386-392]`. Pipeline stages are the ocx CLI: the test pipeline reuses `ocx package test` and `ocx package push --cascade --format json` "unchanged" `[src: adr_ocx_mirror_test_pipeline.md:319]`. Consequence recorded: `ocx mirror ...` strips three signing credentials from the child environment (`OCX_IDENTITY_TOKEN`, `OCX_KEY_PASSWORD`, `OCX_SIGNING_KEY`), so the mirror refuses those names in `sign:` refs `[src: adr_mirror_signing.md:72-83; mirror-yml.md:1197]`. Dependency-edge cost of linking `ocx` itself was measured: 160 of 743 packages `[src: adr_ocx_crate_binding.md:§4]`.

### 1.6 Signing identity, upstream signatures, SBOMs, referrers, verification

All from the ratified discussion (2026-09-02) and `adr_mirror_signing.md` (D1-D6), shipped in 0.6.1.
- **Identity of mirrored output.** Mirror signs packages it *produces* (github, url, pypi legs) with its own identity, keyless by default (`id-token: write` in rendered jobs) or key; **rationale: two distinct claims, "upstream key K signed D" versus "the mirror vouches for D"** `[src: mirror-signing.md:67-72; mirror-yml.md:1175-1213]`. `sign:` is a mode-tagged block with one `Ref` grammar (literal, `env://`, `file://`), refused at load for literal secrets; one-way door on names and grammar `[src: adr_mirror_signing.md:277-300]`. Rejected: a minimal passthrough, inferred mode, mode-field-plus-env-names options (D1 options 1-3, `:211-262`).
- **Fail closed.** With `sign:` set, a signing failure fails the package and no further tag advances; "a silently unsigned package and a silently dropped signature are the same defect class" `[src: adr_mirror_signing.md:94-100,454-470]`. Known window: a landed push is not rolled back `[src: :468-471]`. Alternative rejected: sweep-only signing (cannot cover platform manifests, F3) `[src: :69-92,418-427]`.
- **Carriage (registry copy only).** Upstream signatures and referrers copied verbatim, destination digest equals source digest; the copy adds no signature and never verifies; subject lands before referrers; depth ceiling 2, count ceiling 64 per subject; cosign `.sig/.att/.sbom` sidecar tags byte for byte; a sidecar tag already at another digest is skipped and counted; ECR refusing a referrer manifest fails the package; no `If-Match` in v1 `[src: adr_mirror_signing.md:577-650; mirror-signing.md:88-98]`. Rejected: referrers API only (no testable good path), sidecar sweep only (drops cosign v3 default shape), copy-time verification (`mirror-signing.md:96-97`).
- **SBOM.** Owner 2026-09-01: "SBOM: no, only the signatures"; the mirror never generates one, but copies every referrer upstream attached `[src: mirror-signing.md:17,88-92]`. **Reversal proposed 2026-11-13, parked, not ratified:** SBOM source order upstream SBOM, syft opt-in, built-in minimal generator; re-signing on `registry sync`; subsets; "the owner ... did not confirm the reversal in those words" `[src: signing-dogfood-mirror.md:61-64,74]`. 0.6.5's SBOM items concern ocx-mirror's own release artifacts `[inf: CHANGELOG.md:15,37,43]`.
- **Upstream signatures at ingest (A).** Not carried or checked. Verification of upstream bytes is digest-based only (D-update above). `[inf]` no record covers cosign or SLSA verification of a GitHub release asset before re-hosting.
- **Backfill.** `package pipeline sign` signs only subjects with no signature candidate, `--identity/--issuer` narrow "already signed", `--force` signs again `[src: adr_mirror_signing.md:666-820; cli.md:344-353]`.
- **Trust anchor (client).** Index entries declare `publishers` (the `[[trust.policy]]` signer vocabulary); the client verifies each package; "a mirror or proxy never becomes the trust point (owner, 2026-11-13)"; threat T2 covered because "the mirror holds no signing identity" `[src: ocx/.claude/artifacts/adr_publisher_trust_distribution.md:26,32,148]`. Rejected: the 2026-10-25 draft (index bot checks signatures, TUF-signed index) `[src: :26-28]`. Mirror consequence in the dogfood record: "a mirror that rewrites the catalog re-signs with its own key; the client still verifies every package against `publishers`" `[src: signing-dogfood-mirror.md:51-53]`; re-signing appends the mirror's signer and keeps upstream entries `[src: :64]`.
- **Threat model.** Upstream, the network and answering registries are attackers; the execution environment and whoever writes the destination registry are trusted (owner ruling 2026-08-14) `[src: ocx-mirror/.claude/rules/security-threat-model.md:1-60]`.

### 1.7 Publisher identity, namespace, claim, announce

- **Namespace = vendor identity, not publisher.** Owner chose vendor-identity namespaces (`kitware/cmake`) over publisher namespaces (`ocx-contrib/cmake`), overriding the research recommendation; rejected a privileged `library`-style root tier; closed the impersonation gap with a mandatory `upstream {org, repository_url?, disclaimer?}` object and first-claim human review (G-04) `[src: index/.claude/artifacts/adr_namespace_policy.md:75-150,296-325; decision_log_2026-07-16.md:215-240]`. Vendor-org namespaces are "the convention for all third-party mirrors" with pilot `bazelbuild/bazelisk` `[src: design_spec_announce_initiative.md:113 (E-P1)]`.
- **Ownership.** `owners[].github_id` numeric id mandatory (survives login recycling); transfer through the human-reviewed `owners[]` path; first-come first-claim; namespace immutable, no rename, migration = new claim plus deprecate old `[src: adr_namespace_policy.md:261-295]`.
- **Announce.** Always a reviewed pull request (never a commit to the default branch); REST API default, `--transport git` for GitLab job tokens; PAT only on day one (`ocx-bot` machine account for the fleet, classic PAT because fine-grained PATs cannot fork or PR public repos); one shared `ocx-contrib/index` fork for the whole fleet; "copy and own" grimoire's announce Rust parts, no shared crate; adoption one package first, fleet later `[src: design_spec_announce_initiative.md:27-38 (S1-S12), 108-121]`. Announce is additive: `--tags-from-file` never removes a committed tag, yank markers survive; a partial version announces only `X.Y.Z` `[src: mirror-yml.md:1303-1337]`. Mirror owner ids go into the root's `owners[]` so the machine lane (G-19) can auto-merge `[src: design_spec_announce_initiative.md:110]`.
- **Claim.** `ocx package claim` opens the first-claim PR; `announce` refuses an unclaimed namespace; `--upstream-org/-repository-url/-disclaimer` carry ND-9 `[src: system_design_index_claim_command.md:19-27,1095]`.

### 1.8 Marking a mirror as mirrored; upstream takeover

- **In the artifact:** the ADR planned four annotations (`image.source` = upstream release URL, `image.version`, `image.created`, `image.title`) `[src: adr_ocx_mirror.md:802-816]`. **Not what shipped.** Shipped: `org.opencontainers.image.source` = the *mirror repository* and `.revision` = `GITHUB_SHA`, both auto-filled from CI, plus free-form `annotations:`; the doc says `image.source` "names the mirror repository, not the upstream project" because GHCR uses it for package linkage `[src: mirror-yml.md:1260-1287; crates/ocx_mirror_spec/src/lib.rs:274-279]`. A repository grep finds no writer of `image.version` or an upstream URL `[src: grep, ocx-mirror/src and crates]`. So an ocx mirrored package carries no machine-readable upstream origin in the manifest `[inf from absence]`.
- **In the index:** the `upstream` object on the root (`org` required; `repository_url`, `disclaimer` optional; mandatory by review for third-party seeds; omitted for first-party) `[src: adr_namespace_policy.md:296-325; adr_locked_observation_index_format.md:241 in index repo]`.
- **Upstream author takes over later:** ND-6 and ND-7 only: transfer via reviewed `owners[]`, no rename, new claim plus deprecation (`status: deprecated`, `superseded_by`); the ADR's own Negative consequence says this "will happen at least once" for the 44 seeds `[src: adr_namespace_policy.md:150-157,261-285]`. No technical hand-over flow (key rotation, `publishers` change, tag adoption) is recorded `[inf from absence]`.

### 1.9 Licensing, consent, takedown

Plain statement: **nothing recorded for licence checking, redistribution rights, upstream consent or content takedown** in `ocx-mirror/.claude/artifacts/`, `ocx-mirror/docs/`, `ocx/.claude/artifacts/adr_index_*`, `design_spec_announce_initiative.md` or `index/.claude/artifacts/` (grep over `licen*`, `redistribut`, `takedown`, `DMCA`, `consent`, `permission`; only Cargo `license.workspace` and the items below hit) `[src: grep]`.
