### C2. How each issue got its own commit

- Method A, workers never commit (`plan_settings_follow_ups.md:58-59` PD-2/PD-3, :286): every step ends `git add -A` + `git write-tree`, the report names the tree id; an issue's patch = `git diff --binary <tree before first step> <tree after last step>`. Landing: apply patches with `git apply --index --3way` in the landing order, run ONE full gate on the combined tree, save `git write-tree` as the gated tree, then `git reset -q`; for each issue `git apply --cached <patch>` and record the commit; after the last, `git diff --exit-code <gated tree> HEAD` must exit 0 (proves the series equals the gated tree). A wave lands only from a clean checkout (`git status --porcelain` empty, PD-29); worker scratch goes to gitignored `.agents/.tmp/<pipeline>/`. PD-31: the orchestrator, not workers, runs full gates.
