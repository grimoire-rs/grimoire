# Research: Harness-native marketplace surfaces — prior art

## Metadata

**Date:** 2026-09-15
**Domain:** packaging
**Triggered by:** /hex-discuss harness-native-marketplaces
**Expires:** 2027-03-15

## Direct Answer

Every major harness now has *some* native distribution surface, and nearly all of them converged on the same shape Anthropic shipped first: a `marketplace.json` (or equivalent) registry file in a git repo, pointing at per-plugin manifests declaring skills/commands/agents/hooks/MCP. Claude Code, GitHub Copilot CLI/VS Code, Cursor, Codex, Factory Droid, and Kilo Code are all directly interoperable at the file-format level (several explicitly reuse `.claude-plugin/marketplace.json`). Gemini CLI, Goose, and Kiro use their own extension formats but the same git-repo-as-registry transport.

Projecting Grimoire's OCI catalog into these surfaces is **technically straightforward for transport** (generate a `marketplace.json` pointing at git refs or archive URLs, refresh on publish) but **lossy on everything Grimoire's OCI/lockfile model gives you**: no harness marketplace has a first-class concept of a lockfile, multi-registry resolution, deprecation signaling, or artifact-level integrity beyond opt-in SHA/digest pinning that most users don't set. Claude Code is the deepest (git SHA / archive SHA-256 / npm version as de facto "digest pins"); Copilot's public docs don't document pinning at all; Gemini CLI extensions are explicitly mutable local copies requiring manual `update`. Precedent for exactly this projection already exists and is heavily populated (Vercel skills.sh, Tessl, ClawHub/OpenClaw, SkillsOps/skillctl, `n-skills`, `agent-skills-cli`) — the "generate a marketplace from a registry" pattern is not novel, it's the current normal, and the field is crowded with unofficial aggregators of uneven quality.

The macro trend is convergence on a cross-vendor `SKILL.md` file format (Anthropic's Agent Skills, opened as a standard 2025-12-18) discovered from `$HOME/.agents/skills`, *not* on marketplaces as the primary distribution unit — marketplaces are the packaging/install layer that different harnesses bolt on top of the same underlying file format.

## Key findings

- **Claude Code's marketplace schema is the most fully specified of any harness**, including an explicit version-resolution precedence (explicit `version` → archive SHA-256 → git commit SHA → npm version → "no tracking"), and it is the *only* one of the majors with a documented zip-archive transport and a `command`-source escape hatch for arbitrary fetch logic. [code.claude.com/docs/en/plugin-marketplaces](https://code.claude.com/docs/en/plugin-marketplaces)
- **Claude Code explicitly has no lockfile.** Version strings/commit SHAs/digests in `marketplace.json` are the only update signal, and background auto-updates are disabled by default for private-repo clones because there's no credential-refresh story. [code.claude.com/docs/en/plugin-marketplaces](https://code.claude.com/docs/en/plugin-marketplaces)
- **GitHub Copilot CLI plugin marketplaces intentionally read `.claude-plugin/marketplace.json`** as a fallback location in addition to their own `.github/plugin/`, i.e. GitHub built format-compat with Claude Code's schema rather than inventing a divergent one — direct evidence of convergence at the file level. [docs.github.com](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/plugins-marketplace)
- **Enterprise governance knobs are converging too**: both Claude Code (`extraKnownMarketplaces`, org-managed settings) and Copilot CLI (`managed-settings.json` with `enabledPlugins`/`extraKnownMarketplaces`/`strictKnownMarketplaces`) now ship an org-admin allow/deny layer over marketplaces, as of May–Aug 2026. [github.blog 2026-05-06](https://github.blog/changelog/2026-05-06-enterprise-managed-plugins-in-github-copilot-cli-are-now-in-public-preview/)
- **Gemini CLI extensions are copy-on-install, not live-linked** — `gemini extensions update` is required to pull changes, `--auto-update` is opt-in, and there's no digest pinning described, only `--ref` at install time. This is strictly weaker than Claude Code's SHA pinning. [geminicli.com/docs/extensions/reference](https://geminicli.com/docs/extensions/reference/)
- **OpenAI's Codex plugin directory explicitly has no self-serve publish path yet** ("coming soon" per OpenAI's own docs as of this fetch), meaning third-party catalogs currently cannot register into the *official* directory even if they wanted to — only workspace-managed GitHub marketplaces are self-serve. [learn.chatgpt.com/docs/plugins](https://learn.chatgpt.com/docs/plugins)
- **`extraKnownMarketplaces` in Claude Code has a documented settings/runtime discrepancy**: the docs describe `settings.json → extraKnownMarketplaces` as the source of truth, but discovery in practice reads `~/.claude/plugins/known_marketplaces.json`, and the setting is reported broken in headless/print mode — relevant if Grimoire ever wants a CI-friendly auto-registration story via this mechanism. [github.com/anthropics/claude-code#51806](https://github.com/anthropics/claude-code/issues/51806), [gist: known-marketplaces investigation](https://gist.github.com/alexey-pelykh/566a4e5160b305db703d543312a1e686), [github.com/anthropics/claude-code#13096](https://github.com/anthropics/claude-code/issues/13096)
- **Direct precedent for "generate a marketplace from a registry" already exists at scale**: Vercel's skills.sh (`npx skills add`, claims 18+ compatible agents), Tessl (`npx tessl install`, registry with quality/eval scores, explicitly framed as "npm for agent skills"), and SkillsOps/skillctl (installs *one* source skill into Claude Code/Cursor/Windsurf/Copilot/Kiro in each one's *native* format — i.e., exactly the fan-out Grimoire would need to do). [vercel.com/changelog/introducing-skills](https://vercel.com/changelog/introducing-skills-the-open-agent-skills-ecosystem), [tessl.io/registry](https://tessl.io/registry), [github.com/dgallitelli/skillsops](https://github.com/dgallitelli/skillsops)
- **obra/superpowers is both a plugin repo and a marketplace, and Anthropic added it to the official `claude-plugins-official` marketplace** — concrete evidence that Anthropic curates/re-lists well-regarded third-party marketplaces rather than keeping the official one closed. The exact popularity metric could not be confirmed reliably this pass (see negative findings). [github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json](https://github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json), [github.com/obra/superpowers-marketplace](https://github.com/obra/superpowers-marketplace)
- **The Agent Skills format (not the marketplace layer) is the thing that actually standardized**: Anthropic opened it 2025-12-18; within the following ~3 months Google, JetBrains, AWS, and Block(Goose) all read the same `SKILL.md`/directory convention. Marketplaces remain harness-specific wrappers around this shared file format. [thenewstack.io/agent-skills-anthropics-next-bid-to-define-ai-standards](https://thenewstack.io/agent-skills-anthropics-next-bid-to-define-ai-standards/)
- **The Linux Foundation's Agentic AI Foundation (AAIF)**, launched 2025-12-09, is a real, well-sourced governance body (platinum members: AWS, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft, OpenAI) anchored by MCP, Goose, and AGENTS.md — a plausible future home for a cross-vendor skills/marketplace standard, but as of this research it has not published a marketplace-format spec, only taken stewardship of existing projects. [linuxfoundation.org/press/…agentic-ai-foundation](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation), [techcrunch.com 2025-12-09](https://techcrunch.com/2025/12/09/openai-anthropic-and-block-join-new-linux-foundation-effort-to-standardize-the-ai-agent-era/)
- **The MCP Registry is the closest thing to an OCI-style neutral registry** in this space — open API, npm/PyPI/Docker-Hub-backed package pointers, sub-registry-friendly OpenAPI spec — but as of 2026-07-20 it is still in preview (launched preview 2025-09-08) and scoped to MCP servers only, not skills/rules/agents/bundles. [modelcontextprotocol.io/registry/about](https://modelcontextprotocol.io/registry/about), [registry.modelcontextprotocol.io/docs](https://registry.modelcontextprotocol.io/docs)

## Trends

- **Convergence is on the file format (Agent Skills / `SKILL.md`), not on marketplaces.** Marketplaces are a distribution veneer each harness is independently re-implementing (mostly as "a git repo with a `*marketplace.json` registry file"), while the payload format is genuinely shared. Dated: format opened 2025-12-18, cross-vendor reads confirmed by ~March 2026.
- **A second convergence is happening on the marketplace *schema* itself**, not just the payload: Copilot CLI reads Claude Code's `.claude-plugin/marketplace.json` path directly; Cursor and Factory Droid ship near-identical `owner`/`plugins[]`/`source` shapes; Kilo Code explicitly claims Agent-Skills-spec compatibility for its marketplace entries. This is architecturally significant for a projection strategy — one generated `marketplace.json` shape may satisfy 3-4 harnesses simultaneously, not just one.
- **Governance/enterprise controls are the newest layer** (mid-to-late 2026): both Claude Code and Copilot CLI added admin-managed marketplace allow/deny-lists within the last several months, suggesting the next round of divergence will be in *policy* surfaces, not manifest formats.
- **The unofficial-aggregator layer is large and noisy**: skills.sh, Tessl, ClawHub/OpenClaw, SkillsMP, LobeHub, TerminalSkills, AgentSkillExchange, awesome-* lists — dozens of third-party catalogs already re-publish/re-index the same underlying skills content across harnesses. This is strong evidence of unmet demand for exactly the "project a catalog into every harness" capability, but also evidence the space is already crowded and fragmented, with quality/trust as the differentiator (Tessl and Snyk are explicitly positioning on skill *evaluation/security*, not just distribution).
- **No harness-native marketplace has adopted OCI as transport.** All of them are git-repo-centric (occasionally npm or plain HTTP zip). Grimoire's OCI-first model is not what any of these surfaces expect natively — a projection would need to render OCI-backed content out to a git-shaped or zip-shaped view for each target.

## negative:

- **`obra/superpowers` GitHub star count could not be reliably confirmed.** One search-engine summary claimed "170,000+ stars," a direct WebFetch of the repo page returned "287.0k stars." Both numbers are implausible for this repository relative to its GitHub visibility and are very likely fetch/summarization artifacts (WebFetch runs content through a small extraction model prone to misreading rendered star-count widgets). Treat any specific star count for this repo as unconfirmed; only the qualitative claims (it exists, has a companion marketplace repo, and is listed in `claude-plugins-official`) are corroborated by the raw `marketplace.json` file itself.
- **Cross-harness "N tools support Agent Skills" counts are inconsistent across sources**: one source says 18+ agents (skills.sh marketing), another says "roughly 40 products" (agentskills.io showcase, dated June 2026), another says "32 tools" (thenewstack.io, dated ~March 2026 milestone). These are likely measuring different things (spec-compliant vs. marketplace-listed vs. showcase-listed) and none was verified against a primary inventory page in this pass — cite the specific source's number, never a blended one.
- **GitHub Copilot CLI plugin versioning/pinning semantics were not found in any fetched primary doc.** The official `plugins-marketplace` page details `marketplace.json`'s required fields and hosting locations but is silent on update cadence, SHA pinning, or lockfile-equivalent behavior. This is a real gap, not just an omission in this report — worth a follow-up direct fetch of `docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference` before drawing conclusions about Copilot's lossiness relative to Claude Code.
- **OpenAI Codex plugin manifest schema (field-level) could not be extracted.** The canonical URL (`developers.openai.com/codex/plugins`) redirects to `learn.chatgpt.com/docs/plugins`, whose fetched content describes plugin *contents* (skills, MCP servers, hooks, browser extensions) and *install paths* but explicitly punts manifest schema/versioning/pinning detail to a separate "Build plugins" guide not fetched in this pass.
- **JetBrains Junie's CLI-level "extension marketplace" claim rests on a single third-party GitHub issue thread** (`ScriptedAlchemy/agent-bundle#710`), not a JetBrains primary source. The JetBrains Marketplace plugin page confirms the *IDE plugin* install path but says nothing about a CLI-native skills/plugin marketplace. Treat the CLI marketplace claim as unconfirmed.
- **Zed does not appear to have a first-party skills marketplace UI/registry** — all "Zed skills marketplace" search hits are third-party catalogs (LobeHub, SkillsMP, AgentSkillExchange) indexing Zed-relevant skills, not a Zed-hosted registry. Zed's own docs describe local skill folders only.
- **OpenClaw/ClawHub numbers are marketing-page claims** ("3,286 skills," "5,400+ skills," "thousands," "npm for AI agents") sourced from OpenClaw's own promotional pages and third-party aggregators, not a neutral count. No primary API/stats page was checked for a canonical figure.
- **Sourcegraph Amp's plugin manifest format was not found** — sources describe plugin *behavior* (hooking events, adding tools, standardizing policy) but no manifest filename or schema surfaced in this pass.

## leads:

- **`extraKnownMarketplaces`/`known_marketplaces.json` discrepancy in Claude Code** — worth a focused lane if Grimoire ever wants a "one command registers our catalog as a Claude Code marketplace" flow; the settings-vs-runtime-cache split and headless-mode breakage directly affect whether that flow can be scripted/CI-driven. See [github.com/anthropics/claude-code#51806](https://github.com/anthropics/claude-code/issues/51806).
- **Copilot CLI plugin versioning/pin semantics** — undocumented in the pages fetched here; a follow-up lane should fetch `cli-plugin-reference` directly and/or test empirically (install a plugin, mutate the source repo, observe whether Copilot CLI silently re-pulls) before any lossiness claim about Copilot specifically is finalized.
- **SkillsOps/skillctl's native-format fan-out mechanism** — it already does per-target-harness format translation (Claude Code, Cursor, Windsurf, Copilot, Kiro) from one source skill. Worth a deep-dive on its actual transform logic as a possible reference/prior-art for Grimoire's own per-client materialization, independent of the marketplace-hosting question.
- **MCP Registry's sub-registry OpenAPI spec** — since it explicitly supports third parties standing up compatible sub-registries pointing at npm/PyPI/Docker Hub, worth checking whether Grimoire's OCI-backed artifacts could register there as a "package pointer" without needing a parallel marketplace-specific mechanism, at least for the MCP-descriptor artifact type.
- **AAIF governance roadmap** — no marketplace-format spec published yet per this pass, but given its platinum membership (Anthropic, Google, Microsoft, OpenAI, AWS all present) it is the most likely venue for a future cross-vendor marketplace-format standard; worth a calendar check every few months rather than a deep dive now.
- **Tessl's and Snyk's skill-security/evaluation framing** — both position on trust/evaluation of skills rather than raw distribution, which is adjacent to (and potentially competitive with) any Grimoire provenance/integrity story; worth a dedicated competitive lane if Grimoire's pitch leans on trust rather than just packaging.
