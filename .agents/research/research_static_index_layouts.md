## Cross-cutting trade-offs evidenced

- Name-prefix (Cargo, 1/2/3/2+2 chars) vs hash-bucket (CocoaPods md5 prefix, TUF sha256 `path_hash_prefixes`, 16,384 bins) vs no directory (conda, flat content-hash filename). The TUF spec frames hashing as "consistent hashing" for spreading targets [spec]; no source measures name-prefix skew.
- Content-addressed shards (conda `immutable`, Debian by-hash, TUF versioned names, OCX digest files) need no revalidation, only the root; mutable-path layouts (Cargo, CocoaPods, OCX package root) need ETag per file and CDN invalidation [Cargo doc]; OCX bans CDN caching of `*.json`.
- Single mutable root scales with unique names, not versions: conda index 0.15-0.67 MB per subdir; Cargo has no root listing at all (no static catalog enumeration, no static search).
- Retention of old generations: conda ~1 week, Debian current + 2 previous, TUF delete after ~1 h with 404 -> retry latest and never delete old root; no source describes retention on a full-site-replace host (GitHub/GitLab Pages), only a 1 GB site limit (sibling artifact).
- Whole-file stores (Homebrew, winget, Helm, lunr) give local search for free but grow linearly; every sharded ecosystem (Cargo, npm, PyPI, conda) delegates search to a server or the solver.
- Delta formats lose to full or sharded fetch at the cold-start/long-idle edge: JLAP (conda) and pdiffs (Debian).

## negative:

- No source found for Homebrew combined-file sizes, Nix channel current sizes, winget index size, Pagefind internal format spec, or any static host's retention of replaced deploys.
- No ecosystem found that offers full-catalog search from plain static files except Homebrew/winget (whole local index) and Pagefind-style bundles.
- Cargo RFC does not compare name-prefix vs hash sharding; CEP 16 gives no integrity procedure or fallback.
