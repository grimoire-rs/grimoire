Verdict, one Claude-shaped document for all: **yes for Claude, Copilot, Codex, Qoder, OpenClaw** (same JSON, `.claude-plugin`, `.github/plugin`, `.agents/plugins` copies installed a `./a/b/c/foo` plugin in each [P-q6; Codex/Qoder/Copilot/Claude all OK]); **very likely for Droid, Junie**; **unverified for Cursor** (no client access; a Stripe production `.cursor-plugin/marketplace.json` uses `./providers/cursor/plugin/`, entry `version`, `author`, `owner.email` [github.com/stripe/ai]). Divergences to avoid in a shared document:
1. `metadata.pluginRoot`: Copilot prepends it even to `./`-prefixed sources (probe: `./claude/foo` + `pluginRoot ./claude` -> `.../claude/claude/foo`; [github/copilot-cli#2200](https://github.com/github/copilot-cli/issues/2200)). Claude ignores it for `./` sources. Omit.
2. `owner`: required by Claude/Copilot/Qoder, ignored by Codex; `email`, if present, must be a valid address (Copilot rejected `a@b`: `owner.email: Invalid email`; Cursor schema `format: email`). Emit `owner.name` always, `email` only when real.
3. Names: intersection is lowercase `[a-z0-9]([a-z0-9-]*[a-z0-9])?`, plugin and marketplace, marketplace <=100 chars; no `.` (Codex mkt), no `_` (Copilot).
4. Junie's native array key is `extensions`, but it also reads `plugins` [junie-jar]; the shared file works via `.claude-plugin/`.
5. Claude-only object sources vanish silently in Codex (skipped) and fail Cursor's schema: use `./` strings only.
6. Cursor lint schema is stricter than its docs (see Unknown keys). If Cursor needs the strictest form, emit its file as `{name, owner, metadata.description, plugins[{name, source, description}]}`; otherwise the shared shape.

## Q3. Qoder
Has a plugin format and a marketplace, a near-verbatim clone of Claude Code's.
- Manifest `.qoder-plugin/plugin.json`, falling back to `.claude-plugin/plugin.json` (`Ktn=[".qoder-plugin",".claude-plugin"]`, `$Ne`); only `name` required; fields `version displayName description author homepage repository license keywords dependencies commands agents skills outputStyles workflows hooks mcpServers settings` [docs plugins-reference; probe `plugins validate` needs one of `commands/ skills/ agents/ hooks/hooks.json output-styles/ workflows/ bin/ .mcp.json mcp.json`].
- Marketplace file `.qoder-plugin/marketplace.json` > `.claude-plugin/marketplace.json` > root `marketplace.json` [qoder-js `hVA`]; docs say only "Location: `marketplace.json`" and "compatibility with Claude not stated", the bundle proves the read order.
- Probe: the unmodified Claude-shaped repo (`.claude-plugin/marketplace.json`, tree `claude/foo/.claude-plugin/plugin.json`, extra keys `$schema`, `x-grim`, `unknownKey`) added and installed via `qodercli plugins marketplace add <dir>` / `plugins install foo@mp8`; same for 4-deep source [P-q5, P-q6].
- Add sources: git URL (ssh/https), `org/repo` shorthand, local dir, direct `marketplace.json` URL [docs plugins.md]; scopes `user|project|local`; update `qodercli plugins update <p>`.
- Components: skills, agents, commands, hooks, output-styles, workflows, `bin/`, `.mcp.json`. **No `rules`** component in the plugin format [docs plugins-reference]. Not tested: whether plugin skills render with vendor metadata.
- Not needed: a separate `.qoder-plugin/marketplace.json`; the Claude file is read (second in order). A Qoder-specific file would only be for a Qoder-specific tree.

## Q4. OpenClaw and Junie
- **OpenClaw** [oc marketplace.ts]: reads only `.claude-plugin/marketplace.json` or root `marketplace.json`; needs `plugins[]` with `name`+`source`; entry `source` string is a path inside the root (escape rejected) or `github|git|git-subdir|url|path` object; also imports Claude's `~/.claude/plugins/known_marketplaces.json`. Bundle detection per plugin: `.codex-plugin` > `.claude-plugin` > `.cursor-plugin` > root `plugin.json` (prior file `research_plugin_support_matrix.md`). Claude file suffices.
- **Junie** [junie-jar; docs]: native file `.junie-extension/marketplace.json` uses key `extensions` (JetBrains, upfera, BrayanCaro repos) with entries `{name, source:"./extensions/x", description, version, author{name}, category, homepage, keywords}` and per-extension `extension.json` `{name, description}`; **Claude file is checked first**, so a repo carrying both is read through `.claude-plugin/` (static reading of bytecode, not run; Junie needs auth to start). `ExtensionInfo`/`ExtensionsService` detect `skills/`, `agents/`, `commands/`, `guidelines/`, `.mcp.json` by directory (also `mcp/.mcp.json` in JetBrains repo, `hooks/hooks.json` per docs), no manifest name check found. Sources: git, local, direct URL; state `.junie/extensions.json` (project) / `~/.junie/extensions/extensions.json`. Consequence: writing `.junie-extension/marketplace.json` next to `.claude-plugin/` is dead weight for current Junie.

## Q5. Limits and nesting
- Size: Cursor "whole manifest file must be 10 MB or smaller" [cursor-doc]; OpenClaw manifest 16 MiB, archive 256 MiB [oc :31-32]. Claude `command` sources cap 256 MiB / 20,000 entries [cc-ref] (plugin dir, not catalog). No entry-count or size limit found in Codex (`marketplace.rs` grep for MAX/limit empty), Qoder bundle, Claude docs, Copilot, Droid, Junie.
- Depth: no depth limit; `./a/b/c/foo` installed in Claude, Codex (`cache/deep/foo/1.4.0+...`), Copilot (live path), Qoder [P-q6]. Constraint is only "no `..`, no absolute, no symlink escape" (Claude warns on symlink sources [cc-ref]; Codex rejects non-`Normal` components; Cursor doc; Droid doc).
- Trailing slash (`./x/`) works in Cursor's real file; not probed elsewhere, so emit without.

### Recommendation
1. One `MarketplaceDoc` renderer emitting Claude shape: `name`, `owner{name}`, `metadata.description`, `plugins[{name, source:"./<client>/<plugin>", version, description}]`; no `pluginRoot`, no `$schema`, no object sources, no top-level `version`.
2. Write only the files that change the tree: `.claude-plugin/` (Claude + Qoder + Junie + OpenClaw, Droid fallback, Copilot fallback), `.agents/plugins/` (Codex), `.github/plugin/` (Copilot, since it prefers it over the Claude file and needs the Agent Plugins tree), `.cursor-plugin/` (Cursor). Skip `.junie-extension/` and `.factory-plugin/` (shadowed / translated).
3. Marketplace and plugin names: `[a-z0-9]([a-z0-9-]*[a-z0-9])?`, <=100; avoid `claude`, `anthropic`, `official`, `qoder`+`marketplace|plugins`, `claudeai-`.
4. Derived version `X.Y.Z+<12hex>` goes byte-identical into entry and plugin manifest; `+` is safe in all tested clients.
5. Add a probe-backed acceptance test per harness that installs from the generated repo (Claude, Codex, Copilot, Qoder are scriptable offline as done here).

negative:
- Cursor and Droid clients not run; Cursor tolerance of `version`/`author` entry fields rests on docs plus one production file (stripe/ai), and its repo lint schema is stricter.
- Junie precedence (Claude file first) and Junie's acceptance of a Claude-shaped tree come from bytecode only; the CLI did not run a marketplace add (needs auth).
- Copilot is closed source; schema behavior is by probe (1.0.88) and may change; its update-detection algorithm is undocumented.
- Qoder read from a minified bundle; docs never state `.claude-plugin/marketplace.json` compatibility.
- Entry-count limits: none found for any client except manifest byte caps (Cursor, OpenClaw).

leads:
- Run Junie 1468.30 with a token in a throwaway `HOME` and `--extensions-default-location` to confirm `.claude-plugin/` precedence, Claude-tree acceptance and `+build` handling.
- Probe Cursor (or scrape `cursor/plugins` validate output) with `./x` sources and entry `version`; check Cursor's `minClientVersions` semantics for a future per-client gate.
- Confirm Copilot's update detection for a git-URL marketplace (copy vs live) with a `+build` version.
- Codex `.cursor-plugin` fallback (lookup list) and `.claude-plugin` migration import (openai/codex#19372) if the repo omits `.agents/plugins/`.
