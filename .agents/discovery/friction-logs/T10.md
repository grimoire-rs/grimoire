# Friction log: T10 own-index golden path (author → publish → index → colleague installs)

## Context

The persona is an engineer at a company that already has a GitHub-backed
container registry and has never used grim beyond installing the binary, who
wants the team's internal skills to be findable and installable by every
colleague through the company's own package index rather than the public one.
Starting point: `grim` on `PATH`, an empty project directory, no prior
`grimoire.toml`, no registry configured, and no index repository. The goal
was to trace, and where safe execute, the full path from "I wrote a skill"
to "a colleague ran `grim install`" using only the published docs pages.
Written by a subagent with no repository access, from the published docs
pages and the grim binary only.

## Pros and cons

- Good: `introduction.md` has a "Where to next" list that puts *Host Your
  Own Index* right after *Concepts*, so the team-index need is signposted
  from page one, not buried.
- Good: `artifacts.md` gives an exact, copy-pasteable minimal `SKILL.md`
  (two-field frontmatter) — I used it verbatim and `grim build` accepted it
  first try.
- Good: `commands.md`'s `grim build` entry and `grim build --color never`
  itself agree — the table columns (Kind/Name/Path/Layer Digest/Status)
  matched what the docs implied a "dry run for authors" would show.
- Good: `hosting-an-index.md` "Host Your Own Index" is the closest thing to
  a single page that narrates the whole loop — scaffold, push, fill, gate,
  use — in that order, with runnable commands at each step.
- Good: `package-index.md`'s `metadata.json` table is precise enough to
  hand-write a pointer without ever needing to run the indexer.
- Bad: my first `publish.toml` guess for a company registry
  (`registry = "ghcr.io/acme"`) was wrong and `grim publish --dry-run`
  rejected it with a data error — the quickstart's `--registry ghcr.io/acme`
  (a full host+prefix used for *consuming*) primed me to write the same
  shape into a *publish* manifest, where `registry` must be a bare host and
  the org segment is a separate `repository_prefix` field, documented only
  under "Repository namespace" further down `publishing.md`.
- Bad: no single page states the manifest's "conventional source path"
  rule (`skills/{name}/` relative to the manifest file) next to the
  `publish.toml` example that uses it — I had to grep forward past three
  unrelated `###` sections (support channels, namespace) to find "Conventional
  source layout" and confirm my directory guess was actually the default.
- Bad: authoring and index-hosting are two separate top-level pages
  (`publishing.md` and `hosting-an-index.md`) with the connective tissue
  — "announce" — split again into a third page (`package-index.md#announcing`).
  A first-timer doing this for real has to hold all three open at once.
- Bad: `hosting-an-index.md` calls the npm scaffolder tool a one-command
  loop ("npx … init", "git push"), but that tool and its `publish.toml` (a
  *second*, index-side manifest, "preserved" and never regenerated) is easy
  to confuse with the per-repo `publish.toml` from `publishing.md` — same
  filename, different repo, different job.
- Bad: the "combined layout" (`--with-skills`, one repo owns skills and the
  index) is mentioned only in a collapsed aside inside `hosting-an-index.md`
  ("One repo for both") — a reader who wants exactly that (small team,
  simplest possible setup) has to know to look for it rather than being
  routed there.

hit at line 756, "### The publish.toml format". Copied the shape:
`registry` (required, plain host) + `[skills.<name>]` sub-table with
`version`. First attempt used what quickstart primed me to write:

```
$ cat > $S/proj/publish.toml <<'EOF'
registry = "ghcr.io/acme"

[skills.hello-review]
version = "0.1.0"
EOF
$ grim publish --dry-run --color never; echo "exit=$?"
./publish.toml: registry 'ghcr.io/acme': must be a plain registry host (e.g. 'registry.example' or 'localhost:5000')
exit=65
```

Guessed wrong — this is the one place I got a hard error and had to go back
to the docs mid-task. Re-read forward in the same file and found
"### Repository namespace {#batch-publish-namespace}": `registry` is a bare
host, and a company org prefix is a separate `repository_prefix` field
(`{prefix}/{name}` replaces the default `{kind-subdir}/{name}`). Fixed it:

```
$ cat > $S/proj/publish.toml <<'EOF'
#:schema https://grimoire.rs/schemas/grim-publish.schema.json
registry = "ghcr.io"
repository_prefix = "acme/skills"

[skills.hello-review]
version = "0.1.0"
EOF
$ grim publish --dry-run --color never; echo "exit=$?"
Kind   Ref                                     Digest               Tags                Status
skill  ghcr.io/acme/skills/hello-review:0.1.0  sha256:6fbca0decfc7  0.1.0,0.1,0,latest  dry-run
exit=0
```

Dry run succeeded, state word `dry-run` matches what `commands.md` and the
`--dry-run` flag description promised ("Companions are still... packed...
zero registry mutations occur either way").
