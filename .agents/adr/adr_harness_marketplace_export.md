## Context

Phase 1 shipped `grim export plugin`, `marketplace.toml`/`marketplace.lock`
and `grim update --marketplace` (v0.14.3). Phase 2 turns a curated
`marketplace.toml` into a **git marketplace repo** that harnesses add: one
marketplace file per harness at that harness's own path, each pointing at a
plugin tree rendered for that harness, regenerated by a scheduled CI job that
opens a PR on diff. The owner's decisions in the dossier (`## Decisions`) are
binding: curated view, plugins only, commands deferred, separate git repo,
floating entries, removal on drop, renderer drift fixed by hashing the
rendered tree, indexer fixed first. One ratified requirement — the
incremental skip — is proposed for deferral (D1, open question 1).

Verified seams (grim HEAD 31bc6009):

- `marketplace.toml` top level is `RawManifest { plugins }` with
  `deny_unknown_fields` (`src/export/marketplace.rs:94-99`); `name`, `owner`,
  `description` are rejected as reserved (`:104`, check `:136-141`).
- The declared export path — load, advisory lock, per-plugin staleness,
  `resolve_marketplace`, `plugin_input`, `export_plugins` — is
  `src/export/stage.rs:278-365`; the lock is written after placement only
  when a plugin was stale, dropped, or the lock absent (`:357-364`).
  `is_stale` compares only the per-plugin declaration hash
  (`src/export/resolve.rs:102-107`).
- The version is computed **before** rendering from member lines
  (`stage.rs:532` → `family::plugin_version`, `src/export/family.rs:124-137`),
  client-independent.
- Output naming is `<dir>/<plugin>.<client>[.zip]` (`stage.rs:1278`),
  existing outputs are refused without `--force` (`stage.rs:1291`), staging
  is a `.grim-export-*` tempdir inside the output dir (`stage.rs:674`).
- Families: Claude = claude, droid, junie, openclaw; Agent Plugins = copilot,
  codex, cursor, agents; every other client, Qoder included, → none
  (`family.rs:82-89`).
- `ExportReport` is `{items:[{plugin,client,family,format,path,version,members,omitted}]}`
  (`src/api/export_report.rs:50-67`); `ExportError` has 18 variants,
  classified in `classify_export` (`src/error.rs:360-385`); exit codes are
  `src/cli/exit_code.rs:19-60`. The rendering boundary appends an "upgrade
  grim if a newer version wrote this" hint to any serde `unknown field`
  message (`src/error.rs:267-276`).
- Marketplace files may not be written through a symlink:
  `store::atomic_write` (`src/store/atomic_write.rs:32`) is the plain form,
  `atomic_write_through_symlink` (`:82`) the one to avoid.
- `grimoire-components` is GitLab-only (`gitlab.com:grimoire-rs/components`,
  `templates/{setup,publish}.yml`).
- `grimoire-indexer` enrich runs `describe` unconditionally and sequentially
  (`grimoire-indexer:src/enrich/index.ts:262`, `:340-350`); `compileIndex`
  `rmSync`s `outDir` (`grimoire-indexer:src/data/index.ts:166`). The daily
  `refresh.yml` lives hand-written in `grimoire-index` and only dispatches
  `pages.yml` (`grimoire-index:.github/workflows/refresh.yml:14-35`).

## Industry Context & Research

- `research_marketplace_manifest_schemas.md` — one Claude-shaped document
  serves Claude, Copilot, Codex, Qoder, OpenClaw (probed), likely Droid,
  Junie; avoid `metadata.pluginRoot`, object sources, `_` and `.` in the
  marketplace name; `owner.email` must be a real address; entry and manifest
  `version` must match byte for byte. Junie and OpenClaw read
  `.claude-plugin/` first; Qoder reads `.qoder-plugin/` then
  `.claude-plugin/`.
- `research_marketplace_multi_harness_root.md` — one root with several
  marketplace files, same name; each probed harness reads only its own file;
  `./x` sources repo-root relative; `../` rejected. Precedents: `stripe/ai`,
  `grafana/ai-marketplace`.
- Generated-marketplace prior art (Round-1 review, gap #9): `apm`, `aipm`,
  `stripe/ai` and `wshobson`'s marketplace all **rebuild the generated tree
  in full** on each run; none keeps an incremental render cache.
- `research_derived_version_compat.md` — output-hash identifiers (Go/Terraform
  `h1:`, wheel `RECORD`, Claude Code's own hash of copied files for `command`
  sources); scheme counters; tool version in invisible cache keys only; a new
  table under a closed parser is "backward-compatible, not
  forward-compatible".
- `research_marketplace_ci_write_path.md` — `GITHUB_TOKEN` PRs trigger no
  `pull_request` checks; a GitHub App token does; GitLab `CI_JOB_TOKEN`
  cannot open MRs; fixed bot branch force-updated = one superseded PR;
  public-repo schedules die after 60 inactive days; bot proposes, check
  validates, human merges; pin the CLI by a sha256 literal.
- `research_marketplace_hosting_prior_art.md`, `research_url_marketplace_trust.md`,
  `research_marketplace_multi_version.md`, `research_incremental_pages_builds.md`,
  `research_marketplace_phase2_recon.md` — git is the only transport all
  targets accept and the only one consumers can pin; one version per plugin
  per marketplace; enrich is the measured index bottleneck.

**Key insight:** the owner's render-speed concern is the **index** build (400+
artifacts, sequential `describe`). Marketplace regeneration runs in the
marketplace repo's own CI, over a curated set of tens of plugins, so a full
render there costs a minute or two and never lengthens the index build. The
committed-state skip that the incremental requirement implies carries the
largest defect surface in the first design, and it buys nothing that matters
at this scale.

## Decisions

### D1 — Marketplace repo generation model (central decision)

| Option | R | P | S | U | O | Σ | Note |
|---|---|---|---|---|---|---|---|
| **A. Stateless full regeneration: resolve from `marketplace.lock`, render every `(plugin, client)`, place only trees whose inventory or bytes differ from disk; ownership by convention** | 3 | 3 | 3 | 2 | 3 | **34** | No new file, no state to trust or tamper; matches all prior art. Cost: every run fetches every member (curated set, marketplace CI, off the index build); not `--offline` |
| B. Committed state file (`.grim-export.json`) with per-pair skip key, tree digest, recorded report row | 3 | 2 | 1 | 3 | 1 | 25 | Round-1 review: stale-key, tamper, forward-compat and ownership defects (spec B3/B4, quality B1, security B2, codex B3/B4/B6); a new frozen path |
| C. Skip keys on `marketplace.lock` `[[plugin]]` rows | 2 | 1 | 2 | 2 | 2 | 21 | Rows are `deny_unknown_fields` (`RawPluginHash`, `src/lock/grimoire_lock.rs:104-111`): an older `grim update --marketplace` exits 78; lock churn on every grim upgrade |
| D. Skip when a pre-computed version equals the committed marketplace entry | 3 | 2 | 2 | 1 | 1 | 23 | Circular under D7 (the version exists only after rendering); misses description and logo edits |

**Chosen: A.** The first draft scored A at U1 and O2. That under-rated it:
the no-diff guarantee holds without a skip, because placement compares
bytes; and a state file is a second source of truth an attacker or a hand
edit can steer. **This deviates from the ratified "incremental export"
requirement** — open question 1. The skip returns as an additive,
two-way change if a measured run ever needs it (D13).

**Ownership by convention** (no recorded state):

- For each client in the marketplace client table (D2), grim owns the
  directory `./<client>/` **when that client is selected**, and the client's
  marketplace file **when the file is absent or its document `name` equals
  `[marketplace].name`**.
- Everything else in the repo — `README.md`, `LICENSE`, CI files,
  `marketplace.toml`, the lock, `.github/` itself — is never touched.
- **First adoption**: an existing non-empty `./<client>/` whose marketplace
  file is missing or carries another `name`, or an existing marketplace file
  with another `name`, is refused 65 `untracked-destination` unless
  `--force`.
- **Removal**: under a selected client's `./<client>/`, every entry not in
  the current render set is removed (a dropped plugin's tree, stray files). A
  table client that is not selected, and whose marketplace file carries
  `[marketplace].name`, was dropped: its file and `./<client>/` are removed.
  An unselected client without such a file is left alone.
- Consumer effect of removal: Claude users see the plugin as "not found in
  marketplace" and keep the installed copy unless their admin sets
  `forceRemoveDeletedPlugins` (dossier); Claude's `renames` map is deferred
  (it needs history grim does not keep).

Reversibility: two-way for the generation model (a skip is additive later);
one-way for the tree layout and file paths (D2).

### D3 — Marketplace document

Every file has the same shape, serialized from fixed-order structs, 2-space
pretty, one trailing `\n` (`family.rs:250-254`), entries in plugin-name byte
order:

```json
{
  "name": "grimoire",
  "owner": { "name": "Grimoire", "email": "team@example.org" },
  "metadata": { "description": "Curated grim packages as harness plugins" },
  "plugins": [
    { "name": "team", "source": "./claude/team",
      "version": "1.4.0+3f9a0c12b7de", "description": "Team skills" }
  ]
}
```

- `owner.email` only when declared. `metadata` only when a description is
  declared. No `$schema`, top-level `version`, `metadata.pluginRoot`,
  `category`, `tags`, `author` or `homepage`; each is additive later.
- Entry `version` and `description` are byte-identical to that client tree's
  `plugin.json`.
- `plugins` may be `[]`: a zero-plugin marketplace is valid (D5).
- A plugin that is empty for a client (D5) is absent from that client's file
  only.

Reversibility: two-way (harnesses read it, grim does not).

### D4 — `[marketplace]` table in `marketplace.toml`

| Option | R | P | S | U | O | Σ | Note |
|---|---|---|---|---|---|---|---|
| **a. One optional `[marketplace]` table: `name`, `owner = {name, email?}`, `description?`, `clients?`** | 3 | 2 | 3 | 3 | 3 | **33** | Groups marketplace-level data; top-level keys stay reserved |
| b. Un-reserve top-level `name`/`owner`/`description` | 3 | 2 | 2 | 2 | 2 | 27 | Mixes listing metadata into the plugin namespace; no home for `clients` |
| c. Separate `marketplace.meta.toml` | 1 | 3 | 1 | 1 | 2 | 20 | Second file, loader and path rule |

**Chosen: a.**

```toml
[marketplace]
name = "grimoire"                       # ^[a-z0-9]([a-z0-9-]*[a-z0-9])?$, ≤64
owner = { name = "Grimoire", email = "team@example.org" }   # email optional
description = "Curated grim packages"   # optional, ≤500 UTF-16 units
clients = ["claude", "copilot", "codex"]                    # optional, D2 table only
```

- **Name rules.** Lowercase, with no `.` (Codex) and no `_` (Copilot). The
  loader refuses:
  - any name containing `anthropic`, `claude`, `official` or `qoder`
    (R2-15: a superset of Qoder's own reserved patterns);
  - Claude's reserved names `agent-skills`, `knowledge-work-plugins`,
    `inline`, `builtin`, `skills-dir`, `synced`, `github`, `gh`, `npm`,
    `pip`, `uv`, `cargo`.
- **Owner rules.** `owner.name` must be non-empty. `owner.email` must match
  `^[^@\s]+@[^@\s]+\.[^@\s]+$`.
- Every violation exits 65 `Manifest`.
- **Validated by the shared loader for every command.** `marketplace::load`
  validates the table for `export plugin`, `export marketplace` and
  `update --marketplace`, so a bad table exits 65 everywhere (acceptance row
  in Validation). Only `export marketplace` **requires** the table. Absent,
  it exits 65 naming it. The table is outside every declaration hash, so
  adding it never re-pins a plugin.
- Top-level `name`, `owner` and `description` stay reserved. The rejection
  message gains "use `[marketplace]`".
- **Compatibility class: backward-compatible, not forward-compatible.**
  - Every phase-1 manifest parses unchanged.
  - A grim that predates the table exits 65 on any manifest carrying it. That
    includes phase-1 pipelines pinned to v0.14.x (`export plugin`,
    `update --marketplace`) the moment a curator adds `[marketplace]` (see
    Migration).
  - Mitigation:
    - the existing unknown-field hint says "upgrade grim";
    - the maintenance job pins a grim that has the subcommand;
    - `configuration.md#marketplace-toml` states the minimum grim version.

Reversibility: one-way for key names and grammars (loosening is additive).

### D5 — `grim export marketplace` CLI

```
grim export marketplace [--marketplace <PATH>] [-o, --output <DIR>] [--force]
```

| Flag | Meaning |
|---|---|
| `--marketplace <PATH>` | Manifest; default `./marketplace.toml`; phase-1 file-name rules |
| `-o, --output <DIR>` | Output root; default = the manifest's directory |
| `--force` | Adopt existing paths the ownership convention does not cover (D1) |

- **No `--client`.** Clients come only from `[marketplace].clients` or the
  default set (D2). A repo's shape lives in the repo, not in the job
  invocation, and never in the runner's `[options].clients`.
- Not accepted: positional refs, `--name`, `--project`, `--plugin`, `--zip`,
  `--version`, `--description`, `--logo`, `--client`.
- Global `--format json`, `--progress` and `--offline` apply. Offline needs
  every member in the local store, since every run renders.

**Input.** `marketplace.toml` + `marketplace.lock` through the phase-1
declared path (`stage.rs:278-365`):

- advisory `ConfigFileLock` on the manifest;
- stale plugins re-resolved, fresh ones carried;
- `project` plugins from their own fresh lock;
- the lock written after placement under the phase-1 rule (`:357-364`).

**Additional lock.** A second advisory lock on `<canonical output root>/.grim-export`
is held from before staging through placement. It serialises two manifests
that share one output root. The sidecar `.grim-export.lock` is removed on
drop. Contention exits 75 `locked`.

**Marketplace-only input rules.**

- Declared `logo` files and `path:` members must resolve inside the
  manifest's directory. Symlinks are refused (65 `InvalidLogo` / `Manifest`).
- `export plugin` inputs are unchanged, so these rules narrow nothing that
  already exists.
- Logo reads are capped by bytes read (`take(MAX + 1)`), not only by
  `metadata().len()`. That hardening applies to both commands.

**Render and place.** Every run renders every selected `(plugin, client)`
into the staging dir. For each tree:

- **Compare** the staged inventory with the on-disk inventory at
  `./<client>/<plugin>` (D6).
- If they are equal, the row is `unchanged` and nothing is placed.
- If they differ, the staged tree is placed. An owned tree is replaced
  through the existing aside-then-rename path (`place`, `stage.rs:1321`).

**Order of operations.**

1. Write the marketplace files that changed (the ownership claim, R2-9).
2. Place trees.
3. Remove what D1 marks for removal.
4. Write the lock.

Marketplace files are written with plain `store::atomic_write`, and only when
their bytes differ. Any error before the first placement writes nothing. A
failure mid-placement leaves a state that the next run repairs, because every
run re-renders everything.

**Empty cases.**

- A plugin with no member a client can carry is left out of that client's
  file, with a stderr warning and a report row `empty`. Any existing tree for
  it is removed. One harness's incapacity must not block the others.
- A plugin that is empty for **every** selected client exits 65
  `EmptyPlugin`.
- A marketplace declaring **zero** plugins is valid. It writes catalogs with
  `plugins: []` and removes existing trees.
- `grim export plugin`'s `NoneDeclared` error is unchanged.

**Idempotence.** A second run with no upstream, manifest or grim change places
nothing and writes nothing. Every tree is byte-equal to
`grim export plugin --client <c>` for the same plugin.

**Module placement.**

- New orchestration module `src/export/marketplace_export.rs`: client table,
  ownership, compare, removal, documents and report.
- `stage.rs` gains only the split between staging and placement, plus a
  layout-aware final path.

Reversibility: one-way (CLI frozen at 1.0).

### D6 — Tree inventory, comparison, filesystem safety

**Inventory.** A tree's inventory is the sorted list of
`(entry name, exec bit, sha256 of bytes)` for every regular file under the
root. It uses the zip writer's walk (`archive::collect`/`entry_name`), which
never follows a symlink. `unchanged` means the staged and on-disk inventories
are equal. A symlink, special file or unsafe name on disk counts as a
difference, so the tree is replaced, never followed. The same inventory feeds
the version (D7).

**Exec bit.** grim carries the **source** exec bit only. Files grim generates
are non-exec. Files copied from a member keep the exec bit they were staged
with (always off for registry layers, which carry no modes). Git records only
the exec bit, so nothing else can flip. Directory output of `export plugin`
is unchanged. The first draft's mode normalization is dropped.

**Containment, beyond phase-1 `contained`.**

- **Ancestors.** Every path component from the output root down to each owned
  path — `./<client>/`, the tree, the marketplace file and its parents — is
  checked with `symlink_metadata`. A symlink, a non-directory, or on Windows a
  junction or other reparse point makes the run exit 65 `UnsafeEntry` before
  anything is placed.
- **Tree walk.** The walk never follows a symlinked tree root. Removal
  unlinks a symlink at an owned path and never descends into it.
- **Empty parents.** Empty-parent removal stops at the output root. It never
  removes `.github/`, `.agents/`, `.claude-plugin/` or `.cursor-plugin/`
  unless grim created that directory and it is empty. `.github/` itself is
  never removed.
- **Unsafe names.** Before placement, a rendered tree is refused 65
  `UnsafeEntry` when it holds names that collide under case folding in one
  directory, or platform-reserved names. Reserved means `CON`, `PRN`, `AUX`,
  `NUL`, `COM1`–`COM9` and `LPT1`–`LPT9` (with or without an extension), a
  trailing dot or space, or `:`, `*`, `?`, `"`, `<`, `>`, `|`. This check is
  marketplace export only, because a repo is checked out on every OS. Phase-1
  `export plugin` inputs are unchanged. Cross-platform fixture tests cover it.
- **Required tests.** A symlinked `claude/`, a symlinked `.github/plugin/`,
  a symlinked tree root and a junction (Windows rig).

**Staging.** A `.grim-export-*` tempdir inside the output root, removed on
every exit path.

- Stale `.grim-export-*` directories older than the current run are swept
  with a warning.
- The docs recommend a `.gitignore` line `.grim-export*`. It covers the
  staging dirs and the transient lock sidecar.
- Line endings are grim's (`\n`). Curators on Windows with `core.autocrlf`
  add `* -text` for owned paths (documented).

### D7 — Plugin `version` derivation

Re-scored under the declared drivers:

| Option | R | P | S | U | O | Σ |
|---|---|---|---|---|---|---|
| **a. Rendered-tree hash per `(plugin, client)`, version field excluded** (owner, ratified) | 3 | 2 | 2 | 3 | 2 | **29** |
| b. Member-digest lines + `scheme\t<n>` counter (research recommendation) | 2 | 3 | 2 | 1 | 2 | 25 |
| c. Status quo (member digests only) | 3 | 3 | 3 | 1 | 1 | 28 |
| d. grim version in the hash | 3 | 1 | 3 | 1 | 2 | 24 |

**Chosen: a — the owner's ratified decision.** The scores are close to the
status quo. The tie-breaker is U, the ratified objective: a renderer fix or a
description edit must reach string-comparing harnesses. Under (b) or (c), a
committed byte change can ship under an unchanged version, which Claude and
Qoder then skip.

**Canonical form, unambiguous.**

1. Render the whole staged tree with `plugin.json` `version = <base>` (no
   suffix).
2. Take the D6 inventory as a JSON array of `[entry name, exec bit, "sha256
   hex"]` tuples, sorted by entry-name bytes, serialized compact. JSON
   string escaping makes every record self-delimiting.
3. suffix = the first 12 hex of the sha256 of that serialization.
4. Rewrite `plugin.json` with `<base>+<suffix>`.

Required test (codex B2 counterexample): a tree with files `a` and `b` must
not hash equal to a tree with one file whose name is
`a\n<sha of a>  b`. The first draft's `h1:`-style line format failed that
case.

**Properties and costs.**

- Per-client versions. Trees differ per client (README omission line,
  translated `.mcp.json`, vendor metadata), so versions differ. Each
  marketplace file carries its own tree's version.
- Zip and directory share the version.
- The circularity is removed by step 1. The README carries no version
  (`family.rs:190-216`).
- **Accepted cost:** any grim change to README, `ONRAMP` or "Omitted for"
  text re-versions every plugin for every client.
  - A golden test pins README and `ONRAMP` bytes, so such a change is
    deliberate and release-noted.
- A hybrid that adds member lines to the hash is rejected. It would
  re-version a byte-identical re-publish.

**Scope.** `grim export plugin` and `grim export marketplace` use one
derivation. The trees must be byte-equal.

**Frozen wording** (amends phase-1 D6 and D11; aligns with `stability.md:33`):

- **Frozen:** only the grammar `<base>+<12 lowercase hex>`.
- **Current behaviour, changing only with a release note:** identical
  rendered bytes of a `(plugin, client)` give an identical version.
- The phase-1 D11 row "version grammar + hash input" becomes "version
  grammar".

**Value and meaning changes.**

- Every phase-1 export gets a new suffix once.
- Description and logo edits now move the version.
- `export plugin --format json` `version` can now differ per client for one
  plugin; it used to be one value per plugin. D11 row and release note.
- Tests to change: `test_s006` flips its version assertion and keeps its lock
  assertion. `_suffix` in `test/tests/test_export_plugin.py:171` and in

### D8 — JSON report, errors, exit codes

`grim export marketplace --format json` uses a **sibling report type**
(`MarketplaceExportReport`). The frozen `export plugin` shape is untouched.

```json
{"items":[
  {"plugin":"team","client":"claude","family":"claude",
   "path":"/abs/repo/claude/team","version":"1.4.0+3f9a0c12b7de",
   "action":"unchanged",
   "members":[{"kind":"skill","name":"plan","lock_name":"team-plan","pinned":"ghcr.io/acme/team-plan@sha256:…"}],
   "omitted":[]}],
 "files":[
  {"client":"claude","path":"/abs/repo/.claude-plugin/marketplace.json",
   "action":"written","plugins":["team"]}]}
```

`action` for `items`:

| Value | Meaning | Other fields |
|---|---|---|
| `written` | Rendered tree placed (new or changed) | — |
| `unchanged` | Rendered inventory equal to disk; nothing placed | `members`/`omitted` complete, since every run renders |
| `removed` | A tree under a selected or dropped client's dir, not in the render set, deleted | `version` null, `members`/`omitted` `[]`, `family` from the client |
| `empty` | The plugin carries nothing for that client, so it is not listed | `path` = the tree path it would occupy (absent on disk), `version` null, `members` `[]`, `omitted` = every member with its reason |

Other `items` rules:

- `path` is always the absolute tree path.
- **Order:** rows for current plugins first, in plugin byte order, then
  client order (`[marketplace].clients` order, else table order). Then
  `removed` rows, sorted by `(client, plugin)` byte order.

`files`:

- One row per marketplace file, in client order, then removed files by
  client name.
- `action` is `written`, `unchanged` or `removed`.
- `plugins` holds the sorted names listed, `[]` when removed.
- Plain output has two tables: `Plugin | Client | Version | Action | Omitted`
  and `Client | File | Action | Plugins` (count). Every key is always
  present. The report is emitted only on success.

**Errors and exit codes.** No new `ExportError` variant, no new exit code, no
new `ErrorReason`:

| Failure | Exit | Variant / reason |
|---|---|---|
| Flag grammar (clap) | 64 | clap / `Usage` |
| `[marketplace]` missing or invalid (name, reserved name, owner, email, `clients` outside the table with a served-by hint) | 65 | `Manifest` |
| Marketplace-only logo or `path:` member outside the manifest dir, or a symlink | 65 | `InvalidLogo` / `Manifest` |
| Plugin empty for every selected client | 65 | `EmptyPlugin` |
| Symlinked or non-directory ancestor, junction, case collision, reserved name | 65 | `UnsafeEntry` |
| Existing path outside the ownership convention, without `--force` | 65 `untracked-destination` | `OutputExists` |
| Output-root or manifest lock contended | 75 `locked` | lock error |
| Everything else (lock, resolver, access, staging, rename, member conflict, fs) | as phase-1 D9 | unchanged |

The hand-written table test (`error.rs:1253`) needs no new row. The plan
still re-checks it for every reused variant's new message.

Reversibility: one-way per row.

### D9 — Maintenance job contract

**Flow (both forges):**

1. Install grim (pinned).
2. Run `grim update --marketplace <M> --format json` and
   `grim export marketplace --marketplace <M> --format json`. Both reports go
   to `$RUNNER_TEMP` / a `mktemp -d` **outside the checkout**.
3. Run the policy gate.
4. If `git status` is empty, exit 0.
5. Commit as the bot.
6. Deliver in PR/MR mode (default) or push mode (opt-in).

**Inputs.**

- `grim_version`: exact `vX.Y.Z`, no `latest`.
- `grim_sha256`: the literal digest of the x86_64 musl archive, verified
  instead of the release sidecar.
- `manifest`: default `./marketplace.toml`.
- `mode`: `merge-request` or `push`, default `merge-request`.
- `branch`: default `grim/marketplace`.
- `token`.
- `max_file_bytes`: default 10 MiB.
- Optional `registry`, `registry_user` and `registry_password`.

**Policy gate.**

- Parse `git status --porcelain=v1 -z --untracked-files=all --no-renames`,
  matching exact paths. `--no-renames` gives every record exactly one path,
  so there is no `R`/`C` pairing to parse (R2-5). A changed path that is a
  symlink in the working tree fails the gate.
- The allow-list comes from the export JSON, never from any state:
  - `marketplace.lock`;
  - each reported marketplace file;
  - `<client>/**` for every client in `files` (current and `removed`).
- The gate fails on:
  - anything outside the allow-list;
  - a path matched by `filter=lfs` in `git check-attr`;
  - any file over `max_file_bytes`.

**Delivery.**

- Fixed bot branch, `git push --force-with-lease`: one open PR/MR, rewritten
  in place.
- GitHub PR body: `gh pr create|edit --body-file`, built from validated
  report fields (plugin names pass `SkillName`, pins are digests), capped at
  60 000 characters.
- `${{ github.head_ref }}` and workflow inputs are never interpolated inside
  `run:`. They pass through `env:` only.

**Concurrency.** GitHub uses
`concurrency: {group: grim-marketplace, cancel-in-progress: false}`. GitLab
uses `resource_group: grim-marketplace`.

**Triggers.** A schedule (daily default), a push to the default branch that
touches `marketplace.toml`, and manual runs. The index never dispatches the
marketplace job. No `-o ci.skip`: the pipeline a bot push triggers is a
cheap no-op.

**Tokens.**

- **GitHub App** (preferred, open question 2):
  - a `actions/create-github-app-token@<sha>` token down-scoped with
    `permission-contents: write`, `permission-pull-requests: write` and
    `repositories: <this repo>`;
  - never `workflows`;
  - the App private key lives in an Environment restricted to the default
    branch.
- **GitHub fallback**: `GITHUB_TOKEN` plus the repo setting. Its PRs run no
  `pull_request` checks, so the gate runs in-job and the docs say so.
- **Job permissions**: top-level `permissions: {contents: read}`, with write
  only on the regenerate job.
- **GitLab**: a project access token.
  - MR mode needs **Developer** with `write_repository`: the push options
    `-o merge_request.create -o merge_request.target=$CI_DEFAULT_BRANCH` open
    the MR.
  - **Maintainer** only for push mode onto a protected branch.
  - Premium on gitlab.com. The 365-day expiry is noted.
  - `CI_JOB_TOKEN` is not supported.

**Keepalive (GitHub, public repos).** A separate job with only
`actions: write` calls `PUT /repos/{r}/actions/workflows/{id}/enable`.
Whether that resets the 60-day timer is unverified (research lead L2). It is
a validation item, and the docs name the manual re-enable.

**Verification job.**

- Trigger: `on: pull_request` only, never `pull_request_target`, on
  **every** PR, with no `paths:` filter, so a required check never waits in
  Pending (R2-6). Credentialed steps (private-registry login) run only when
  the head repo equals the base repo.
- Steps (R2-1, supersedes the Round-1 "empty temp root"):
  1. Check out the PR head. Run
     `grim export marketplace --marketplace "$GITHUB_WORKSPACE/marketplace.toml" --format json > "$RUNNER_TEMP/verify.json"`
     **in place**: logos, `path:` members and `project` plugins resolve where
     they live, and nothing is copied.
  2. Require `git status --porcelain=v1 -z --untracked-files=all --ignored=matching -- marketplace.lock <every table marketplace file> <every table client dir>/`
     to print nothing. git's own status is the compare set: an edited,
     deleted, added or ignored owned file, a dropped client's leftovers and a
     re-resolved lock all surface.
  3. Run `claude plugin validate` over `.claude-plugin/marketplace.json` and
     every `claude/<plugin>` tree (Round-1 gap #6).
- A curator PR editing only `marketplace.toml` fails this check until the
  bot PR lands. The docs describe that two-step flow.

**Documented repo prerequisites.**

- A protected default branch.
- The verification job as a required check.
- CODEOWNERS on `<client>/**`, marketplace files and `marketplace.lock`.
- "Dismiss stale approvals" on.
- The bot identity not on any bypass list.

**Trust-model alignment.** A compromised upstream artifact is out of scope
per `adr_artifact_trust_model.md:83-85`. PR review shrinks the exposure
window; it is not a control against it. **Merge = publish**: Copilot
enterprise `autoUpdate` (2026-08-26) and Cursor's automatic refresh reach
fleets within minutes of a merge (Round-1 gap #4). Push mode removes even
the window and is documented as for trusted private registries only.

**Size budget.** Consumers who want only their tree clone sparsely. The
guide documents `--sparse .claude-plugin claude` for Claude, and Codex's
`--sparse` equivalent.

**Where it ships.**

- GitLab: a new component `templates/marketplace.yml` in
  `grimoire-components`.
- GitHub: a workflow documented in the new marketplace guide and carried
  verbatim by `grimoire-rs/marketplace`, because `grimoire-components` is
  GitLab-only today (D12).

### D10 — Indexer changes (`grimoire-indexer`)

**Probe first.** Per package, run `grim fetch <ref> --digest-only` (one HEAD
request).

- If the digest is unchanged and the package is not in this run's re-describe
  slice, carry the seeded record forward. No `describe`, no contents fetch.
- Otherwise take today's path: `describe`, plus a contents fetch on a moved
  digest. Set `describedAt = now`.
- The description companion keeps its own `--description --digest-only`
  probe on every run.

**Backstop is a rotating slice inside enrich.** Each run re-describes the
⌈N/7⌉ packages with the oldest `describedAt`, so coverage is full weekly and
the load is flat.

- This catches tag-list-only changes (an old-line patch release) within 7
  days of runs.
- **Deprecation-hiding bound:** a deprecation annotation moves the probed
  ref's digest (`src/oci/annotations.rs:233`), so it shows on the next run.
  A deprecation that does not move the probed ref's digest shows within one
  rotation (≤7 runs of the slice).
- `refresh.yml` in `grimoire-index` stays as is.

**Worker pool.** A bounded pool, `--concurrency` default 8. Failures stay
per-package.

**`describedAt` stays internal.** It lives only in the enrich sidecars and
`enrich.json`. `compileIndex` strips it like `descDigest`, so `all.json` is
unchanged.

**Precondition.** The checkpoint must round-trip every sidecar. The observed
7-of-19 seed gap (`grimoire-indexer:src/enrich/checkpoint.ts:225`
`hydrateFiles`) is fixed first.

**Latency at 400 unchanged artifacts, estimated.** Per run:

- about 800 HEAD probes (artifact and companion);
- about 58 slice describes with their fetches;
- 8 workers.

That is about 1–3 min against about 13 min extrapolated today.

**`/marketplace/` landing page.** An Astro route rendered only when the new
config key `marketplace: { url, name } | null` (default `null`) is set. It
is built after `compileIndex`'s `rmSync`.

- `url` must parse as `https:`. It is emitted as `owner/repo` only when the
  host is exactly `github.com` and the path has exactly two segments. Every
  other URL is emitted as the full URL, as escaped text. `set:html` is never
  used.
- One row per harness:
  - Claude: `/plugin marketplace add <owner/repo|url>`.
  - Copilot, Codex, Qoder, Droid, Junie and OpenClaw: commands verified at
    plan time, each row date-stamped.
  - **Cursor**: the dashboard import path, since there is no CLI command
    (gap #7).
- Each row also shows the `<plugin>@<name>` install form. The page has no
  plugin list.

### Quantified impact (estimates, not measurements)

| Metric | Before | After | Notes |
|---|---|---|---|
| Index enrich, 400 artifacts, unchanged | ~13 min (extrapolated, recon Q1) | ~1–3 min | 800 probes + ~58 slice describes, 8 workers |

| Commits on a quiet day | n/a | 0 | byte-compare places nothing |

### Consequences

**Positive:**

- One render path serves `export plugin` and the marketplace, and the trees
  are byte-equal.
- Renderer and description fixes reach string-comparing harnesses by
  construction.
- There is no bookkeeping file to trust, tamper with or migrate.
- A quiet day commits nothing.
- A failed job leaves the last commit valid.
- Consumers pin the whole marketplace by git ref.

**Negative:**

- Every run fetches every member, and runs are not offline.
- Versions are per client.
- One update prompt per phase-1 export on upgrade.
- Wording changes to README or `ONRAMP` re-version everything.
- `[marketplace]` makes the manifest unreadable to an older grim.
- Owned trees are overwritten, so hand edits are lost.
- Fallback harnesses get Claude rendering.

**Risks:**

- Cross-OS byte determinism is load-bearing for the version.
  - Mitigation: the job runs Linux only, and a Linux vs Windows version test
    runs on the local rig.
- Cursor is unprobed, as are Droid and Junie, which fall back.
  - Mitigation: the Cursor probe is the first spike; fallback smoke tests;
    the docs say best effort.
- GitHub disables the schedule of a public repo after 60 inactive days.
  - Mitigation: the keepalive job and a documented manual re-enable.
- Merge = publish, fleet-wide within minutes.
  - Mitigation: PR default, CODEOWNERS, required verification, and push mode
    documented as unreviewed.
- Registry rate limits on full renders.
  - Mitigation: a curated set, a daily schedule, and optional registry
    login.
